## Representative participant protocol
Recruit actual small-brand owners and specialist operators from larger brands; include multi-store work, mobile, keyboard-only and native screen-reader scenarios. Record an anonymous participant code, role segment, task IDs, device/browser/assistive technology, help given, first completion, store/draft-live identification, scope/spend interpretation and observed issue. Never record real credentials or customer records. Founder feedback is useful but cannot substitute for representative cohorts.

Tasks: find a store-scoped project; edit and safely navigate; answer a missing-input question; review exactly two products; identify the target store and draft/live status before confirming; handle expired review; recover connection; inspect uncertain outcome without duplicate execution; create an agent draft specifying account/reviewer; reach conversation and decisions on mobile/keyboard; export after credit exhaustion. Start each task from a stated fixture; do not coach controls. Do not let test participants run actual merchant writes.

Compute unassisted successes / all attempted representative tasks, including abandoned and failed tasks; acceptance is at least 90 percent. Every participant must identify the intended store and draft/live state before consequential action; no approval may have unintended scope or spend interpretation. An issue cannot be hidden by dropping its task. Repeat corrected flows with affected segments and record original plus retest evidence. Screen-reader checks include headings/landmarks, tab position, selected state, dialog label/focus, error association and live status announcements. Reviewer signs the actual evidence and baseline decision; Codex self-review is not a participant.

Anonymized result template: participant_id, segment, task_id, device, assistive_technology, attempted, completed_unassisted, help, target_store_identified, draft_live_identified, scope_understood, spend_understood, finding_id, retest_ref.
