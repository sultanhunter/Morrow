### Notes for review

- **The `account` route entry** is byte-identical to the one on the P05.T01x Part B branch (title "Account"; components AccountHeader, WorkspacePicker, OrganizationSignupForm), so either PR can land first without a catalogue conflict. The packet §4.5 text names different components and the title "Workspaces"; aligning the packet text is a routine wording change.
- **Login body version.** `composed.loginBodyVersion` is 1, matching `main`. `tests/workspace-web-http.test.mjs` feeds the client's body to the server's `loginStartInput`, so whichever of this PR and Part B lands second fails `npm test` until the flip to 2 (§4.14) is made.
- **The harness export** is a `hook` parameter on `edgePostgresqlJourneys` (`origin`, `listen`, `journeys`) rather than a separate `createEdgePostgresqlHarness()`; the P04 path is unchanged, and the edit stays away from the lines Part B changes.
- **The §4.6 probe** is implemented behind `composed["account.overview"]`; until PR-2 composes the account routes it runs only in fixture mode, and the HTTP build uses the PR-1 rule (restored this load → WorkspaceUnavailable with Sign in; otherwise sign-in).
- **Account and work requests** are built and unit-tested (AC08) but uncomposed: the HTTP port answers `not_in_build` without a request until PR-2 adds the record decoders.
- **AC20 header evidence** comes from Chromium's Network ExtraInfo (what the network stack actually sent), because Playwright's `request.allHeaders()` omits `Sec-Fetch-*` while routing is on. The lab also checks `Sec-Fetch-Site: same-origin`.
