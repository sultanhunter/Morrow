### Notes for review

- **The `account` route entry** is byte-identical to the one on the P05.T01x Part B branch (title "Account"; components AccountHeader, WorkspacePicker, OrganizationSignupForm), so either PR can land first without a catalogue conflict. The packet §4.5 now shows this entry (routine wording, 2026-10-19).
- **Login body version.** `composed.loginBodyVersion` is 2. P05.T01x Part B (PR #10) landed first and its account-mode start accepts only `{"schemaVersion":2}`, so PR-1 starts at v2 (§4.14); the flip was made in the merge with `main`. `tests/workspace-web-http.test.mjs` feeds the client's body to the server's `loginStartInput`, so `npm test` fails if the two disagree again. At v2 the sign-in button at `/` is enabled; the v1 path (a workspace is required) stays tested but is not composed.
- **The harness export** is a `hook` parameter on `edgePostgresqlJourneys` (`origin`, `listen`, `journeys`) rather than a separate `createEdgePostgresqlHarness()`; the P04 path is unchanged, and the edit stays away from the lines Part B changes. Packet §4.13 and §5 now say so.
- **The §4.6 probe** is implemented behind `composed["account.overview"]`; until PR-2 composes the account routes it runs only in fixture mode, and the HTTP build uses the PR-1 rule (restored this load → WorkspaceUnavailable with Sign in; otherwise sign-in).
- **Account and work requests** are built and unit-tested (AC08) but uncomposed: the HTTP port answers `not_in_build` without a request until PR-2 adds the record decoders.
- **AC20 header evidence** comes from Chromium's Network ExtraInfo (what the network stack actually sent), because Playwright's `request.allHeaders()` omits `Sec-Fetch-*` while routing is on. The lab also checks `Sec-Fetch-Site: same-origin`. Packet AC20 now says so.
- **Review findings of 2026-10-19 (AI review, separate context, same model family), applied:** "Go to your workspaces" from an ended session view (signed out, unavailable, probe failed) is now a full document load of `/` (it used to change the URL and leave the same screen); a restore that was entered is resumable again on expiry (AC30), and only a restore that never got a 200 is dropped; sign-out disowns commands still in flight, so none writes a marker back or keeps `beforeunload`; every session view has its own title; a 401 closes an open leave dialog; the drawer no longer puts `dialog` on `<aside>`. The matrix grew by 16 state cases and 5 walks (5 new fixture scenarios), and the packet counts were updated.
- **Deferred to PR-2:** the signup form's "disabled until `Retry-After`" (§4.8, 429 row). PR-1's form shows the 429 copy but does not hold the button; signup is uncomposed over HTTP until PR-2, where AC25 wires and tests the hold.
