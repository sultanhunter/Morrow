## Context

The owner approved decision 7 ("yes to all recommended", Q12), asked for "one main agent and then other sub agetns which can be started by user as required" (Q12), and approved specialists ("yes to both, go with option A and specialists", Q14). On `main`, `listings-run@1` makes one tool-free call per product and the Coordinator is code.

## Decision

1. **One Workflow.** `AgentRunWorkflow` (`agent-run@1`) runs installed agents, the Coordinator and specialists. Admission pins a manifest: release, system-text and tool-catalogue digests, model profile, caps and any spec digest and deadline. Steps carry only ids and codes and re-enter the run lease. At a resume after `inbox.ask` the lease comes from the answer command for a person's run (ADR-0022 item 9; it grants nothing), from `admit_mandate_run` for a mandate run (ADR-0024 item 6), or from ADR-0028 item 6's renewal for a specialist. At most 2 questions; 72 hours unanswered ends the run. Code, never model text, derives the outcome. The approved stale-run sweep (ADR-0023 "What stays") extends to `agent-run@1`, closing a run whose lease ended unrenewed (`lab:agent-runs` case).
2. **Each tool call is a durable step:** lease re-entry (for a specialist, an open child task and unpassed deadline too); replay of a recorded result; validation; ids in scope; the authority decision; a worst-case hold; dispatch. The decision depends on the run kind:
   - routed runs and specialists: `decideDelegation`;
   - mandate runs: `decideAutomation`;
   - the Coordinator: a stated check in code, the requester's live grants ∩ the Coordinator's fixed grant set (item 8) ∩ rules and stops.

   New `lab:agent-authority-workers` rows deny each kind when a term fails. After a crash, reads run again, internal writes return their first record, and `computer.*` answers `tool_outcome_unknown`.
3. **A closed tool catalogue.** `ToolCatalogue@1` is generated, digest-pinned data: `mvp.md`'s tools plus `agent.route` and `specialist.draft`, each with its capability, verb, replay class and an 8 KiB result bound. No tool takes SQL, a URL, a role, a store, a recipient, a sender, a credential or a model, and none has an external effect: `proposal.create` makes a digest-bound proposal for the gateway. A skill never adds a tool.
4. **`ModelCall@2` and `ModelResult@2`,** closed and provider-neutral; `@1` stays until `listings-run@1` drains. The broker reads the selection and tools from the run its lease names and refuses `prefix_mismatch` before any request, so the conversation is append-only. Tools go with `strict: true` and `tool_choice` `auto` (`none` on the final turn); T2's contract PR fixes the sent and never-sent fields. An invalid `tool_use` ends the run; an uncertain turn is booked at its worst case and resent at most once.
5. **Untrusted content and its rule** (amends ADR-0011's "Taint is a field only"; P11.T02 enforces it). Untrusted content (product text, email, sandbox outputs, uploads, tool results, reports) enters only as wrapped data naming its source. Model output never sets the tool list, capabilities, scope, recipients, senders or caps. A proposal from a run that consumed `untrusted_external` content keeps that taint through edits; the gateway dispatches it only after a person approves its exact digest, never on an automatic or agent approval; and its card lists its untrusted sources.
6. **Caps for loop runs** (catalogue version 2, owner question 2, as item 12 changes it). Per turn: 64,000 input tokens, counted first, and the effort's `max_tokens` (item 12). Per run: 16 turns (6 for the Coordinator); 4 tool calls per turn and 40 per run; wall time 30 minutes for installed agents and the Coordinator, waits excluded, and for specialists the spec deadline, at most 8 hours with waits counted (ADR-0028 item 6). The turn limit is also bounded by ADR-0026 item 4's per-run USD backstop over the entry's worst-case turn (item 12 gives the values). A turn starts only if the reservation and time cover a final turn; the resend of an uncertain turn (item 4) passes the same check. Before the rate card, loop runs earn no credits, run only on development stores under ADR-0026 item 7's `TestEntitlementSeed` (the G11 path), and count toward the unrecovered-cost cap.
7. **Run turns.** Content lives only in `run_turns` (FORCE RLS); `run_tool_calls` holds ids, codes and digests. Retention is ADR-0031 item 1's. No content reaches Workflow outputs, Queues or logs.
8. **The model-based Coordinator.** One built-in principal per workspace runs `morrow.coordinator`, a role prompt plus up to 15 eligible skills injected by code. Its fixed grant set covers `knowledge.search`, `work.read`, `message.post`, `inbox.ask`, `task.create`, `agent.route` and `specialist.draft`: no store reads, proposals, computer or support tools, and its context excludes customer-tagged items at launch (ADR-0031 item 6). Only a person's act starts it, with that person as requester; never text or a schedule. `agent.route` names one active installed agent on the task's store, once per run. Only the Coordinator delegates.
9. **Model profiles, set at install and changed per agent** (item 12). Each installation, the Coordinator and the workspace's specialist profile hold one `ModelSelection@1` profile, which code sets to item 12's default for its kind; each specialist run takes the specialist profile or the Owner's pick at Start. `governance.model_default.revise` stays `human_only`, held by the Owner, and by Admins for installation targets only. Admission pins the profile and refuses a missing one, substituting nothing.
10. **SpecialistSpec@1 and child runs.** A closed spec, digested with RFC 8785. The model writes the brief (`title`, `objective`, `inputRefs`, `doneCriteria`, `boundaries`) and, refining ADR-0023 11a, picks 1 to 3 skill ids from the eligible list and an `outputContractId` from a closed list. These choose only which skill bodies load and the report's form: code derives the tools and capability ids from the tools the eligible skills declare ∩ the Specialist ceiling (ADR-0028 item 2), never from the chosen ids, and writes every other field. `specialist.draft` grants nothing and never runs in a turn holding a report. A child run has a fresh context and no notebook and ends with a `report@1` artifact, which the Coordinator never reads at launch.
11. **Switches and delivery.** T2 merges the contracts with fakes. A forward migration admits `agent-run@N`. `docs/decisions/agent-loop-staging.json` is committed `off`; production refuses it until G10 and G12. Catalogue version 2 publishes only on the owner's recorded confirmation.
12. **Model and effort per agent** (owner question 1 as the owner changed it, OD-2026-10-23-7). The shop chooses the model and thinking effort of each agent.
    - **Who chooses.** Holders of `governance.model_default.revise` (item 9): the Owner for the Coordinator, each installation and the workspace's specialist profile; an Admin for installations only. Members see each agent's choice and change none, and the per-run choice stays dropped (ADR-0023, "What is dropped"). For one specialist the Owner may pick any offered entry on the Start card (ADR-0028 item 3); the entry is a spec field, so the document's digest binds it. A starter without the capability (Members, after launch) may only pick an entry whose worst-case turn is at most the specialist profile's (ADR-0023 decision 11).
    - **The offer at launch.** Catalogue version 2 has Haiku 5.5, Sonnet 5.5 and Opus 5.5 at `low`, `medium` and `high`, always with adaptive thinking (Opus 5.5 cannot turn thinking off; effort is its only control). `max_tokens` is 5,000, 12,000 and 16,000, version 1's confirmed values, so one call's budget (`modelCallBudgetMs`, at the floor of 128,000 output tokens an hour) is about 197 s, 394 s and 506 s. 64,000 input tokens keep Haiku 5.5 in its US$0.10 / US$0.50 tier. Each release lists the entries it offers, each passing its recorded evals, and always its kind's default; the picker shows only those.
    - **No `xhigh` or `max` at launch.** The send is non-streaming (ADR-0022 item 10, as amended on 2026-10-22). At the floor rate the protocol's 600 s ceiling holds a call whose reply is at most 19,342 tokens, barely more than `high`'s 16,000, and these levels are meant for long outputs. They come with streaming, by a new catalogue version and an ADR-0022 item 10 amendment.
    - **Defaults.** The Coordinator: Opus 5.5 at `high`. The workspace's specialist profile: Opus 5.5 at `medium`. The five installed agents: Sonnet 5.5 at `low`.
    - **When a change applies.** Admission pins the profile (item 1), which also keeps one run on one model and effort, so its cached prefix and thinking blocks stay valid. A change applies from the agent's next admitted run: a run in flight or waiting on an answer keeps its profile; a trigger admitted after the change gets the new one; a Start uses the entry its document binds and is refused `stale` if that entry is no longer offered.
    - **Never authority.** A profile changes no tool, capability, grant, scope, rule, `dataClasses`, credit cap or deadline; code derives only the turn limit and the holds from it. No tool takes a model (item 3), model output never names one, and the api accepts only `{model, effort}` keys of the active version that the target's release lists.
    - **Audit.** Each change is one command through a new definer (M3's `cmd_model_default_revise` is final and stays for `listings-run@1`). It writes an audit record and an activity entry: actor, target (an installation, the Coordinator or the specialist profile), old and new keys, and the catalogue version. No content.
    - **Labels.** On each agent's page and in Settings: "Model" (Haiku 5.5, Sonnet 5.5, Opus 5.5) and "Thinking effort" (Low, Medium, High). Each choice shows its estimated credits for a typical run and the most a run can use, with the line "Applies from the next job. It doesn't change what this agent can do." The Coordinator is shown as "Morrow (main agent)" and the specialist profile as "New specialists". No provider model id is shown.
    - **Money.** ADR-0026 item 5's rate card prices tokens by model, so its margin holds whatever is chosen; the effort changes the worst case, and so the holds. A worst-case turn is 64,000 input tokens at the 5-minute cache-write rate, the dearest input rate (only the fixed prefix is cached, owner question 3), plus the whole `max_tokens` at the output rate. An expected turn is 20,000 input tokens, of which a 12,000-token fixed prefix is written to the cache on the run's first turn and read after, plus version 1's expected outputs (1,200, 2,500 and 5,000 tokens); staging measurements replace these. At Anthropic's prices (per million tokens: Opus 5.5 US$4 in and US$20 out, Sonnet 5.5 US$2 and US$10; cache writes 1.25 times input; cache reads US$0.20):

      | Default | Worst-case turn | Turn limit | Run hold | Expected turn (first turn) | Expected run |
      | --- | --- | --- | --- | --- | --- |
      | Coordinator: Opus 5.5, high | US$0.64 | 6 | US$3.84 | US$0.13 (US$0.19) | US$0.46 (3 turns) |
      | Specialist: Opus 5.5, medium | US$0.56 | 12 | US$3.06 at US$149, US$2.03 at US$99 (its 5% credit cap) | US$0.084 (US$0.14) | US$0.73 (8 turns) |
      | Installed agent: Sonnet 5.5, low | US$0.21 | 16 | US$3.36 | US$0.030 (US$0.058) | US$0.21 (6 turns) |

      A run's hold is the lowest of its turn limit times its worst-case turn, US$7 and its credit cap (ADR-0026 item 4), and the daily backstop counts that hold while the run is open. The turn limit is item 6's (6 for the Coordinator, 16 otherwise), lowered so that it times the worst-case turn fits US$7. For a specialist the 5% credit cap is lower: at most about US$3.06 of vendor cost at US$149 and US$2.03 at US$99, so at the worst case it gets at most 5 turns at US$149 and 3 at US$99, the last a final turn (`cost_budget`); its 12-turn limit binds only when turns cost less, as expected turns do. An installed agent's look-for-work pass holds at most its 1% cap, US$0.61 at US$149 and US$0.41 at US$99 (ADR-0026 item 4). Other entries' worst-case turns: Opus 5.5 US$0.42 at `low` (16 turns) and US$0.64 at `high` (10 turns); Sonnet 5.5 US$0.28 at `medium` and US$0.32 at `high` (16); Haiku 5.5 at most US$0.016 (16). The dearest turn, US$0.64, fits US$7 ten times and US$25 thirty-nine times. A run whose caps cannot hold one worst-case turn of its entry is not admitted (`cap_below_turn`); a run that must call a tool (a specialist, or a mandate run, look-for-work included) needs two, a tool turn and a final turn. The picker says which caps an entry does not fit, counting two turns for these runs.
    - **Time.** At `high` one call's budget (506 s) is more than the Coordinator's former 5 minutes, so item 6 gives it 30: three worst-case calls (1,518 s), or six expected turns at the floor rate (about 3 minutes each). Its 6 turns stay, at most US$3.84. The floor is an assumption until the staging smoke measures each model at `medium` and `high` (OD-2026-10-23-7's decision 37; M3 brief owner question 6); a model below it loses that entry, or gets a lower `max_tokens`, in a new catalogue version.

## Consequences

If the loop misses W4, the G11 demo uses `listings-run@1`.

At the new defaults an Ask is expected to cost about US$0.46 of model use, about four times the Sonnet 5.5 low estimate of US$0.12 (item 12). ADR-0026 item 5's grant rule is checked against this on staging.

Item 12's hold, `cost_budget` and `cap_below_turn` rules were written after the owner's answer, to carry out the change to owner question 1; they await the owner's confirmation with rate card v1 (ADR-0026, Consequences).

## Alternatives considered

- **A Workflow per agent:** many authority paths.
- **The loop in E2B or hosted elsewhere:** the key or the authority would leave Morrow.

## Amendments

### 2026-10-25: teammates in place of specialists (ADR-0037)

The owner's decision of 2026-10-25 (OD-2026-10-25-3, recorded in ADR-0037) changes these items; the text above is kept as approved.

- **Item 8.** Morrow's fixed grant set replaces `specialist.draft` with `agent.propose` (an agent card, granting nothing) and adds `agent.ask`, a teammate call that returns a closed, typed TeammateResult@1 as wrapped, tainting data. `agent.route` names one active teammate of either origin and is used only when the teammate must own the conversation. One call or hand-off per run at launch. Morrow still has no store reads, proposals, computer or support tools.
- **Item 10** is superseded: SpecialistSpec@1 and specialist child runs give way to AgentProposal@1 (ADR-0037 item 4) and the teammate call (ADR-0037 item 3).
- **Items 1, 2, 3, 6, 9 and 12, where they name specialists.** A called or handed-off teammate's run is a routed run: `decideDelegation`, and an installed agent's lease, wall time and turn limit. The catalogue drops `specialist.draft`. The workspace's specialist profile becomes the default for new teammates, shown on each agent card, where a holder of `governance.model_default.revise` may pick another offered entry.
