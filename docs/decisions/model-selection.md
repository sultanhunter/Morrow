# Model gateway design

Decision: ADR-0022 items 10, 11 and 16 (owner, 2026-10-19), as ADR-0027 item 12, ADR-0036 and ADR-0039 (owner, 2026-10-25) amend them. The owner confirmed the catalogue's contents, default, multipliers, token caps, margin, failed-product bounds and member ceiling on 2026-10-19 (ADR-0022, "Owner confirmation of the catalogue values (2026-10-19)"); catalogue version 1 was `active` from 2026-10-19 and is retired. Version 3, version 1 with ADR-0036's default, member ceiling and no unrecovered-cost cap, was published on 2026-10-25 (the owner confirmed its default member ceiling of 4, OD-2026-10-25-2) and is retired. Version 4, version 3 with no run or daily cost cap and 25 products a run for every entry (ADR-0039 item 4, OD-2026-10-25-4: credits are the only spend limit) and with Claude Opus 5.5 at medium and high as its only entries (the owner, 2026-10-26: "we don't want to cheap out on models"; Haiku 5.5 and Sonnet 5.5 leave the catalogue, and low effort leaves too on the owner's answer to question 1 on pull request 82), is `active` from 2026-10-26, with its digest pinned in `model-policy.json`. It replaces the 2026-10-14 selection of OpenAI for text models (canonical sequence 16). The machine-checked record is `model-policy.json`; `npm run verify` validates it.

**Provider-neutral port.** Callers send `ModelCall@1` and receive `ModelResult@1` through the broker; neither names a provider, provider model ID, token limit or price, and `ModelCall@1` names no model selection: the broker reads the selection and catalogue version from the run bound to the lease. In the broker, each catalogue entry names a `ModelProvider` adapter that maps the call to the provider's request and returns a broker-internal `AdapterResult` (with the provider request and model IDs and the raw stop reason). The broker records those IDs in the run manifest, which is where the provider trace IDs of `docs/contracts/model-gateway.md` live, and returns a `ModelResult@1` with only an opaque `traceRef`. Anthropic Claude, through the Messages API, is the first and only adapter. Another LLM is one adapter, one broker credential and one catalogue entry with no change to callers; selecting it is material and needs an owner-approved ADR. There is no automatic fallback to another model or provider, and Anthropic's server-side `fallbacks` parameter is not used.

**Catalogue and selection.** A versioned catalogue lists the allowed models (since version 4 only `claude_opus_5_5`; versions 1 and 3 also listed `claude_haiku_5_5` and `claude_sonnet_5_5`, and `npm run verify` refuses any model but Claude Opus 5.5 from version 4 and in every published version but 1 and 3, an older or newer Opus included, until a reviewed change to its rule) and efforts (since version 4 `medium` and `high`; versions 1 and 3 also listed `low`, which verify refuses under the same rule; `xhigh` and `max` may come in a later version once tests show they help; each is mapped to adaptive thinking, `output_config.effort` and a `max_tokens` cap). The workspace sets a default (Opus 5.5 at medium effort since ADR-0036; Sonnet 5.5 at low in version 1); a merchant may pick another entry per run. Members without the owner's model permission are held to a workspace ceiling of credits per product (by default the default's credits: 4, owner-confirmed on 2026-10-25). For agent-loop runs (ADR-0027 item 12, as ADR-0036 amends it) Morrow, the main agent, defaults to Opus 5.5 at high and every other agent kind (specialists, sub-agents and the installed agents, Listings included) to Opus 5.5 at medium; the Owner may change each agent's model and effort. The server accepts only keys of the active catalogue version, never a model string from the client; `ModelSelection@1` keys are pattern-checked strings, not contract enums, so a catalogue change is not a contract change. Model IDs are Anthropic's pinned snapshot IDs; a new model, multiplier or price is a new catalogue version, a published version never changes (its digest is pinned and verified), and runs record and are booked at the version they used. [Claude models](https://platform.claude.com/docs/en/about-claude/models/overview), [effort](https://platform.claude.com/docs/en/build-with-claude/effort)

**Cost.** Each entry costs a published multiplier (since version 4, Opus 5.5 at 4 and 6 credits a product at medium and high; versions 1 and 3 ran from 1 to 6, Opus 5.5 at low costing 2); the default, Opus 5.5 at medium, costs 4 (one credit at version 1's Sonnet 5.5 low). Thinking tokens are billed as output and count toward `max_tokens`. Credits are the only spend limit (ADR-0039): a run holds its products' credits from the workspace's wallet before any call, and per-call input and output caps, two attempts per product, 25 products a run and the Anthropic Console workspace's monthly spend limit bound spend whatever the selection (catalogue versions 1 and 3 also carried US$7 per run and US$25 per workspace per day, which version 4 removed). Failed products earn no credit, so a run stops after three consecutive failures; their cost is recorded per billing period and, since ADR-0036, capped by nothing else. The verifier rejects any entry whose worst case per product exceeds 90% of its credits' net revenue on the beta plan, after card, Billing, Stripe Tax and international-card fees. Prices are list prices observed on 2026-10-19, not a merchant invoice rate. [Pricing](https://platform.claude.com/docs/en/about-claude/pricing)

**Data.** Only the merchant's request text and the product's catalogue fields are sent. Anthropic does not train on commercial API data by default, deletes API inputs and outputs within 30 days (if flagged by its trust and safety systems, the content up to 2 years and its classification scores up to 7 years), and offers zero data retention only by agreement, which Morrow does not have. Stateful provider features (Files, Batches, code execution, Managed Agents) are not used for merchant content. [API and data retention](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention)

**Images.** Claude does not generate images. The post-launch image capabilities (P17.T02e) keep the recorded OpenAI Images selection (GPT Image 2.5 Sunburst) behind the same port until an owner ADR decides otherwise; no OpenAI credential is bound for the MVP. [Images guide](https://developers.openai.com/api/docs/guides/image-generation)

No model may mint a capability, approval, billing entitlement, credential or its own model selection. Coordinator discovery sees capability metadata allowed by current actor scope; subagents receive authorized contextual references, tool discovery, mandates and budgets. API observations with web search record prompt, locale, model, date and cited evidence; they do not measure consumer chatbot market share or promise citations.

P13 evaluation uses held-out small-brand and specialist tasks, repeats, missing context, conflicting source evidence, malicious retrieved instructions, revocation, refusal, unknown provider effects and recovery. Critical authority failures have zero tolerance. Each role's output, correction effort, completion, latency and total-cost thresholds must be fixed before its trial. No model quality or merchant value has been measured yet; the expected token counts in the catalogue are estimates until the staging smoke runs replace them. P15 researches and releases skills; evaluation evidence links exact model, effort, catalogue version, route, skill, connector and workflow versions.
