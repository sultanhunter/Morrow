# Event and stream contracts

Version: 1.0.0 candidate. Owner: Morrow platform owner. Review: Codex semantic self-review plus schema/fixture checks; integration qualification remains required. Canonical plan sequence: 13. Consumer: P06.

## Shape and ownership

Schemas: EventEnvelope, CommandEnvelope, ErrorEnvelope. Exact field types, nullability, required properties and closed object validation are in schemas/v1/core.schema.json; capability bodies are in capabilities.schema.json. State actors and guards are in state-transitions.json. Representative valid/invalid fixtures are in fixtures/P01.A02.json. Payload references are immutable scope/revision/digest bindings, not storage URLs or bearer credentials.

## Command and query semantics

Event IDs deduplicate delivery. Aggregate revisions order mutations; opaque stream positions support authorized resumption and are never compared as timestamps. An outbox and receiving inbox persist before acknowledgement. Event payloads are permissioned references, not raw private records in workflow history. Consumers detect revision gaps and reconcile from authoritative records. Reconnecting clients request from their last server-issued position under current membership.

## Failure invariant

Duplicate delivery cannot repeat an operation; missing intermediate revisions trigger reconciliation. Failures use ErrorEnvelope and must not leak inaccessible content. Current policy and resource checks apply to all reads, mutations and derived artifacts.

## Compatibility and evidence

Every command/read declares schema version 1. Unknown fields and invalid enum values fail validation; no implicit coercion/default authority. Breaking fields/states/meaning require a new version and explicit migration with retained workflow histories. Additions remain opt-in via negotiated schema versions, not silently accepted fields. Consumers pin reviewed contract revisions. Run npm run verify:contracts and npm run test:contracts for contract fixture evidence; these do not prove production authorization or provider access. Open provider/region/retention/billing targets remain in the decision register and block consumers that need them.

## Binding notes (P06.T01a, write side only)

- **Ordering scope.** Outbox positions are gap-free and commit-ordered **per workspace**: each command appends under its workspace's stream lock, which it holds until COMMIT. Aggregate revisions order each aggregate; every aggregate revision has exactly one event. No order across workspaces is promised.
- **Payload allowlist.** Payloads carry IDs and statuses only, enforced by a database CHECK: `goal.created` `{status}`; `goal.status_changed` and `task.status_changed` `{from,to}`; `task.created` `{goalId,status}`; `task.assigned` `{assignmentId,ownerPrincipalId}`; `question.requested` `{respondentPrincipalId}`; `question.answered` `{answerId}`; `question.cancelled` `{}`. Objectives, criteria, prompts and answers never enter the outbox.
- **Deferred.** The EventEnvelope mapping, `payloadRef`, readers, cursors and delivery belong to P06.T02a; `causation_id` is null for human commands.

## EventEnvelope@2 and the event registry (P01.T02c, ADR-0016 item 6)

- **Replacement.** `EventEnvelope` (@2, `schemas/v1.1/core.schema.json`) replaces the v1 envelope, declared in `schemas/v1.1/changes.json`: the v1 `payloadRef` is an ArtifactRef, and event payloads are not artifacts. Product code never validates or types the v1 envelope (`SUPERSEDED_CONTRACT_USE`).
- **Registry, not a closed enum.** `event-registry.json` binds each `eventType` to its `aggregateType` (always the first segment) and one payload definition. `validateCurrentDefinition("EventEnvelope", e)` is the schema plus the generated selector `validateEventPayload(eventType, aggregateType, payload)`, so an unregistered type or a mismatched aggregate is invalid. Adding a row is additive (a later v1.x minor, whose `since` is any contract minor from 1.1 through the current version); changing, removing or reordering one is a replacement with an ADR. `release-baseline.json` pins every row by the SHA-256 of its JCS form, in order, and `npm run verify:boundaries` fails on a changed, removed or reordered row (`UNREVIEWED_EVENT_ROW_DELTA`) and on an appended row that is not pinned (`UNBASELINED_EVENT_ROW`).
- **Exact selectors are not enough.** The registry, the payloadRef binding below and the `AskAdminReadRecord` reader rules are code rules that only `validateCurrentDefinition` applies. Product code under `apps/` and `packages/` never validates `EventEnvelope`, `StreamFrame` or `AskAdminReadRecord` by the exact `core-v1.1` selector (`REFINED_DEFINITION_BYPASS`, `npm run verify:boundaries`).
- **v1.1 rows.** The eight P06.T01a rows above, unchanged; P07.T03 `conversation.created {subjectKind}`, `message.created {conversationId,status,authorKind}`, `message.status_changed {conversationId,from,to}`, `project.created {goalId}`, `project.revised {}`, `project.pin_changed {pinned}`; P05.T02b `access_request.created {}`, `access_request.status_changed {from,to}`; P06.T01b and P06.T01c `proposal.created {capabilityId,killSwitch}`, `approval.created {proposalId,quorumReachable}`, `approval.status_changed {from,to}`, `operation.status_changed {from,to}`; P05.T01z and P11.T05 `kill_switch.executed {capabilityId,sourceProposalId}`, `stop_proposal.dismissed {}`. Payloads carry IDs and statuses only, at most 512 bytes of JCS; message text never appears in an event.
- **Payload ref and nulling.** `EventPayloadRef` is `{O, W, storeId, kind: "event_payload", id: eventId, revision: 1, digest: sha256(JCS(payload))}`, and its organization, workspace, store and id must equal the envelope's `organizationId`, `workspaceId`, `storeId` and `eventId` (`validateCurrentDefinition` rejects any other ref). The digest is **not** the outbox `payload_digest`: migration 0015 hashes PostgreSQL `jsonb::text`, which is not RFC 8785 (it puts spaces after `:` and `,` and orders keys by length). P06.T02a recomputes `sha256(JCS(payload))` from the stored payload when it builds a ref; binding to a stored column instead needs a forward migration with a JCS digest column. An authorized later fetch by ref resolves the tenant from the session, never from the ref. A viewer who cannot view every payload field gets `payload` and `payloadRef` both null: never a partial object, and no digest of a small payload to brute-force.
- **Visibility.** An event is delivered only when its aggregate is visible: messages by the all-of message rule, conversations by subject, Asks to their owner only (admins never receive Ask events or streams), projects by goal view, access requests to the requester and deciders, proposals, approvals, operations and kill switches by the inbox recipient rules. Inbox state emits no events.
- **Positions.** P06.T02a and P07.T03 seal `streamPosition` per viewer and never emit the gap-free outbox position. `StreamFrame` carries an event, a message delta, a generic `reset` or a heartbeat.
- **Inbox inputs.** question ← `question.*`; approval and quorum exceptions ← `approval.*`; access_request ← `access_request.*`; operation exceptions ← `operation.status_changed`; assignment ← `task.assigned`; mention ← `message.created` (the relay reads mention rows, never the payload); stop_notice ← `kill_switch.executed`; stop_proposal ← `proposal.created` with `killSwitch`, `kill_switch.executed` and `stop_proposal.dismissed`.
