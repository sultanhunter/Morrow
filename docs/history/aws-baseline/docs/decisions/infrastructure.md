# P01 infrastructure decision

Design recorded in canonical plan sequences 16–17 on 6 October 2026. Owner: Morrow platform owner. Implementation selection and documentary review: Codex, under the user's instruction to continue. No account eligibility, paid authorization, provisioning or measured service result is claimed.

Use AWS us-east-1 for the private API, ingress, ingestion, trusted connector/agent workers, authoritative PostgreSQL and artifacts. Use Cloudflare for public assets and DNS. Use Temporal Cloud aws-us-east-1 for orchestration and WorkOS for identity. TypeScript/React remains the shared application stack. AWS infrastructure uses CDK TypeScript; provider configuration is versioned alongside it. One repository keeps module contracts stable while execution and trust boundaries determine separate processes.

## Database and delivery

Aurora Serverless v2 PostgreSQL supplies adaptive capacity. Production has a warm writer and failover reader across two AZs; both begin with a 0.5 ACU planning floor, subject to current engine limits and load results. PostgreSQL 17 is the compatibility baseline. P04 preflights the supported regional engine minor and chooses the tested min/max envelope before deployment. A component cost floor is not evidence this capacity can support the target load. Local development uses PostgreSQL 17 and a local Temporal service. Staging can pause only during explicitly idle integration windows: open connections prevent pause, and resumption adds latency. Continuous webhooks/queues cannot be promised zero idle cost. [Aurora pause constraints](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/aurora-serverless-v2-auto-pause.html)

Private HTML, session endpoints, API, webhooks, streams and private object transfers terminate at regional AWS ingress with AWS WAF. Cloudflare delivers public immutable assets only. No credentials, private payloads or tenant path identifiers go through a public asset Worker. DNS delegation itself does not mean an application request is proxied. This intentionally narrows the earlier general Cloudflare-WAF candidate. Private edge processing would require a new recorded decision and regional configuration qualification. [Cloudflare regional boundaries](https://developers.cloudflare.com/data-localization/how-to/workers/)

## Authority and service boundaries

PostgreSQL owns organizations, workspaces, shops, grants, tasks, proposals, approvals, operations, budgets, usage, artifact metadata and erasure/revocation ledgers. Temporal owns workflow progress, not permission or merchant facts. Histories carry opaque identifiers and safe enums rather than content/secrets. Outbox/inbox delivery bridges the two. S3 owns immutable artifact bytes behind authorization and short-lived transfers. IAM roles separate API, ingestion, trusted workers, credential broker, migration/restore and sandbox launchers. Runtime services have no schema-owner/BYPASSRLS privileges; use transaction-scoped tenant context and test pooled-connection leakage. [PostgreSQL RLS](https://www.postgresql.org/docs/17/ddl-rowsecurity.html)

WorkOS sign-in/SSO/SCIM proves external identity. Morrow memberships and current grants govern access. Shopify connector identity proves eligible installation controls; standalone sign-in resolves Morrow membership separately through verified linking. Connector context does not confer workspace authority; matching email is insufficient. WorkOS staging/US processing terms and production connections need account evidence. SSO and Directory Sync are qualified customer connections with recurring vendor costs, not a free universal connection assumption. [WorkOS pricing](https://workos.com/pricing)

## Untrusted execution

One restricted Fargate task per run, in a separate network/pool. No task IAM role, secrets, database route or direct internet. Artifact access uses a short-lived scope-bound gateway; provider effects use the trusted broker and exact approval/operation record. The network admits only the fixed authenticated egress proxy and broker routes. Egress policy checks URL schemes, host/port, redirect chain, resolved addresses, private/link-local/metadata ranges and DNS rebinding. Browser subrequests and WebSockets must use the same policy. Enforce CPU/memory/time/disk/output quotas, immutable image digest, generation lease and cleanup. Never place different tenants in containers inside one task as an isolation shortcut: they share network and storage. [Fargate task boundary](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/fargate-security-considerations.html)

P12 must prove escape/egress confinement, credential non-disclosure, tenant isolation, cancellation, crashed cleanup and stale-generation denial. Selecting Fargate does not itself qualify these controls. If the selected profile fails, hold activation and change the canonical plan before adopting another runtime. Trusted workflows never execute generated code locally.

## Costs and recovery

cost-model.json records primary rate observations, known component arithmetic and missing terms. The 730-hour warm example is **$217.15 for four selected components**, before networking, storage, usage, logs, staging, additional execution pools and identity/business-service subscriptions. It is neither a full bill nor a provisioning quote. No credits are assumed. A complete current us-east-1 quote and account preflight are P04 prerequisites. The owner requested costs scaling with demand without an arbitrary infrastructure ceiling; per-tenant budgets and reservations remain mandatory.

capacity-targets.json records fixture loads, 99.9% control-API availability and class-specific latency/recovery targets. These are unmeasured. P04/P18 measure failover/restore against five-minute regional DB RPO and sixty-minute RTO; P12 measures durable waits/execution; P17 measures role outcomes and total execution cost. Workers/queues throttle and schedule fairly rather than silently growing cost. Restored environments stay quarantined until erasure, revocation, uncertain operations and orchestration state reconcile.

No deployed state requires migration. This decision replaces the infrastructure candidate; it preserves core contracts and all 18 packages. Later engine, region, trust or provider changes require recorded consequences before implementation.
