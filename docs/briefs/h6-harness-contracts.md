## Goal

Give every later harness PR (H7a to H7e, H9, H10 to H12, H14 and H15) one set of contracts and deterministic fakes to build against, so the runner, the broker, the context engine, memory and the screens agree on shapes before any table or Worker exists. The contracts carry ADR-0041's rules where JSON Schema can state them (ids only to the broker, no turn or time limit, every derived row with an audience and taint, a review verdict that can only block); code carries the orderings and id rules it cannot (`packages/policy/src/harness.ts`, `context-policy.ts`).

## Security notes

- **The broker reads only what the lease names.** ModelCall@2 carries no conversation, so a compromised orchestrator cannot hand the broker a made-up history; the fake refuses a call whose run is not the one attached to the named context (one writer per context), so a valid lease cannot borrow another person's context. H7c's broker must keep both rules against SQL.
- **Permission and budget checks stay in code.** AgentRunSafety@1 lives in the manifest the model never sees; no contract the model reads names credits, a balance or a countdown; no notice code asks the model to wrap up.
- **No model-written authority.** Checkpoints, summaries and plans have no field that can claim an approval, consent, apply or payment; the ledger shows every operation whose outcome is unreconciled as UNKNOWN (`unknownOperationStatuses`: dispatching, submitted, verifying, uncertain and cancel_requested), so a compaction can never present one as settled; a review verdict can only block or raise no objection.
- **Audience and taint on every derived row** (turns, state blocks, checkpoints, the ledger, plans, verdicts, summaries, notebook entries, search hits): `DerivedTaint`, ModelUntrustedSource's kinds and a source count, joined by union and sum (`joinTaint`), so a reader of a stored row loses no kind; person memory has one principal and no admin path in its shape.
- **Every run has an absolute bound.** Every manifest kind names an envelope, upkeep included (admit_upkeep_run issues it and no act renews it), so no lease renews without an expiry; at every step's entry the lease kept covers the step (`leaseRenewalDue`), so the sweep cannot close healthy work `lease_lapsed` mid-call.
- **The broker's only source is SQL.** A provider compaction's opaque block is stored on its checkpoint (`block`), which the next epoch's opening names by id and digest; it is run content on its epoch's clock, deleted with the checkpoint and by redaction.
- Retired codes stay in the enums so old records still validate; `writableEndReason` stops new code writing them.

## Review findings (AI review, separate context, same model family), applied 2026-10-27

- **F1, medium: `cancel_requested` shown as settled.** The ledger's UNKNOWN binding now includes `cancel_requested` (migration 0020: entered from submitted and uncertain while reconciliation continues, and it can still end verifying). One set in code, `unknownOperationStatuses`, which the schema binding is tested against for every `OperationStatus`; JobState's `checking` and the ledger's `unknown` descriptions name it, for the renderer (H7d) and the card's projection (H14).
- **F2, medium: free endings.** `freeRunEndReasons` is pinned exactly: ADR-0039 item 2(g)'s free list less its retired limit endings (`provider_error`, `invalid_output`, `refusal`, `prefix_mismatch`, `lease_ended`, `switch_off`), plus `internal_error` (ADR-0041 item 3(d)) and three readings below. `meteredRunEndReasons` holds the rest, and a test requires the two to cover every live reason exactly once.
- **F3, medium: no stored compaction block.** `ContextCheckpoint@1` gains `block` (`CompactionBlock`, the same definition as `ModelCompaction.continuity`: base64, 1 to 1 MiB), required for `provider_compaction` and null for `fallback`.
- **F4, medium: two taint vocabularies.** H6's two-value `TaintKind` is gone. `ModelUntrustedSource` is the kind set, with the same 19 values and description as H5's, and every derived row carries `DerivedTaint` (`kinds`, `sourceCount`): H5's `RunTaint` without the inline source list. The dangling `RunTaint` reference is gone from H6's descriptions.
- **F5, low: untainted fork fakes.** The fork's checkpoint, ledger, plans and reviews carry the join of what the fork read (products, Listings' result, its item: `product`, `teammate_result`, `result_item`, 30 sources), and item i1 carries `product`; a test requires every fork-derived fake to cover that taint.
- **F6, low: the lease could lapse mid-call.** Chosen here, for the lead to confirm: **a turn step renews the lease at its entry, always** (`leaseRenewalDue`); other steps renew below `renewBelowMs` as item 7 says. The seeds keep the 28-minute call budget that item 8 sizes for 64,000 tokens at `high`, which lowering it to 18 minutes would break. Renewing more often only re-runs admission's checks more often, and every renewal stays inside the envelope. `checkRunSafety` requires `lease.ms` to cover the turn step and `renewBelowMs` to cover a 10-minute step. ADR-0041 item 7's "if less than 20 minutes remain" reads as applying to the other steps; H7b implements it from `leaseRenewalDue`.
- **F7, low: upkeep runs without an envelope.** Every manifest kind now requires `envelopeId`. admit_upkeep_run (H12) issues an envelope from the pinned safety profile, which no act renews (nothing in an upkeep run is the requester's act), so renewal is refused after its absolute expiry. The upkeep profile's envelope values (short: an hour or so of active time, a day of wall time, against a job's 24 hours and 7 days) are catalogue data H12 sets with its upkeep row. This is a tightening reading: ADR-0041 never says an upkeep run has no envelope, and it rejects sliding leases with no absolute bound; item 7's lease-source table could name the envelope admit_upkeep_run issues in a wording note.
