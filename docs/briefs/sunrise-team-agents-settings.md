## Goal

The owner can see who works in the shop (Morrow, the added agents, the one-time specialists and the people), open one agent's page, change how an agent thinks (model and thinking effort), browse the agents Morrow offers and add one through a server-built document, and read Settings: Plan and credits, Email addresses (the shop's Morrow address, with linking marked "Coming soon") and People and roles. Shop knowledge and Files get simple read-only pages.

## Scope

- **Screens** (`packages/workspace-ui/src/screens/`, each in its own file, styled by `styles/sunrise-team.css`): `team.tsx` (Team and the "Change how it thinks" dialog), `agent-page.tsx`, `add-agents.tsx`, `settings-pages.tsx` (Settings home, Plan and credits, Email addresses, People and roles), `notifications.tsx`, `activity.tsx` and `stop-all.tsx` (Activity with Stop all AI work), `library.tsx` (Shop knowledge, Files). Shared Sunrise parts in `src/sunrise/`: the seven agent characters and people initials (`avatars.tsx`), badges, pills, cards, the permission list, progress bars, the thinking picker and the settings menu (`parts.tsx`), and the screens' copy (`copy.ts`).
- **Routes, unchanged** (ADR-0032 item 1): `agents` is Team, `agent` an agent's page, `agent_store` and `agent_listing` Add agents, `knowledge` Shop knowledge, `assets` Files, `settings` the Settings home. The Settings menu follows the board (Plan and credits, People and roles, Notifications, Email addresses, Shopify connection, Activity, then Stop all AI work), and the route contract's six `settings_section` values carry it with no contract change (`settingsRoutes` in `sunrise/parts.tsx`, one place to rename): `usage` Plan and credits, `people` People and roles, `notifications` Notifications, `stores` Email addresses (the shop's own addresses), `governance` Activity with Stop all AI work, and `billing` M3's model default (what a product may cost; it was `governance`). Shopify connection is the existing `connections` route. See open question 1. The sidebar labels stay PR 14's.
- **Data, behind default-off switches.** A UI-only port group (`team.*`, `settings.*`, `library.*`; view models in `src/team-model.ts`) that only the fixture adapter implements. The production build leaves every one uncomposed, so it sends nothing and those destinations show the existing "not built yet" state. T2, T4, T11 and T13 compose them when their routes exist.
- **"How this agent thinks"** shows Haiku 5.5, Sonnet 5.5 and Opus 5.5 at Low, Medium or High. Where governance already exists, it is bound to it: the Listings agent's choice is the workspace model default (`models.list`, `models.reviseDefault`, with the expected revision); a choice above the member ceiling cannot be saved and links to Settings to raise the limit, which this page never does. Every other agent, Morrow and new specialists use `team.reviseThinking` (fixtures only). Only someone the server allows sees the controls; the fixture models the rule (Owner for everything, Admin for added agents only, members for nothing; ADR-0027 item 12).
- **Notifications** (the person's own choices: email per kind, the morning summary's hour, quiet hours; the shop's time zone, the Owner only) are closed values saved with `settings.reviseNotifications` and the expected revision, behind the same uncomposed switch. Emails hold counts and links only.
- **Activity and Stop all AI work.** The list ("What happened", with its filters) is fixture data (`settings.activity`; PR 15 brings the activity log). "Stop all AI work" is wired to the stop that exists: for each linked store, the Listings agent's "Stop AI work" (`agents.listingsStop`, ADR-0005 human_only, no second approver), one command and key per store, sent at once after the person types "stop". The server's `actions.stop` decides who may; agents never see the control. A lost reply stays "not confirmed" with Check again on the same key, never "stopped". Turning AI work back on is each store's own Resume (the server-built document, as Enable). It uses only composed M3 routes, so it works in the HTTP build too.
- **Adding an agent** asks the server for the install document (`team.addDocument`), shows exactly that document (what it may and may not do, the Shopify access it needs, its model, effort and credit limit, and who reviews it), and confirms it by its fingerprint and single-use value (`team.addConfirm`), as Listings' enable does.
- **Tokens:** Sunrise colours enter `docs/design/tokens.json` under a `sunrise` prefix with their contrast pairs; `tokens.css` is regenerated. Option 1's tokens and every other screen are unchanged. When PR 14's tokens land, the prefixed names map onto them in one rename.

## Security notes

- The screens decide nothing. Each change is a command the server (here the fixture) accepts or refuses; a refusal, conflict or unknown outcome shows the existing feedback ("Check again" never reads as saved).
- No input reaches a store, an email or a model. Model and effort are closed keys of the catalogue; the credit limit is a bounded integer; the add confirmation carries only the server's fingerprint and single-use value.
- A face, colour, pill or title confers nothing; the copy says so on Team. No internal words (run, token, digest, scope, prompt and the rest of ADR-0032 item 4) appear in this copy; a test checks it.
- Files has no upload (uploads wait for P09.T05): "Upload a file" is marked "Coming soon". Email addresses sends nothing and links nothing.
- Fixture data is synthetic (Linen & Form); no real shop, person or address.

## Open questions (owner)

1. **Settings sections.** The route contract has no `email` or `activity` section. Until a route-contract PR adds them (PR 14's brief names the same need), Email addresses uses `stores`, Activity uses `governance`, and the model default moves from `governance` to `billing`. One rename in `settingsRoutes` re-homes each.
2. **Stop all AI work** stops what can run today: the Listings agent on each linked store. It becomes one workspace-wide stop when the agent platform (T2/T4) adds one; that is an authority change with its own ADR.
3. Pause, Remove and Renew on an agent's page, Undo and Download on Activity, and changing the sender name or support address wait for their backends (PR 4, PR 15, ADR-0024, T11); they are not drawn as working buttons.
