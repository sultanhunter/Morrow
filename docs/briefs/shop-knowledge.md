## Goal

A shop keeps what its agents should know (its brand voice, policies, product facts, suppliers and decisions) as typed pages with versions and sources. Agents suggest additions; a person accepts or declines each one. Each installed agent keeps its own notebook. Listings can write in the shop's brand voice, with the page entering its prompt only as marked data. A page and all its versions can be deleted before any real content exists.

## Security notes

- **Default off, fails closed.** `docs/decisions/shop-knowledge-staging.json` holds `switch` and `agent_tools` off. Every route answers 503 before body work or a connection; the screen's port methods are uncomposed and send nothing; the tools refuse `switch_off`; `listingsBrandVoice` reads nothing. `edge:check` refuses `switch` on until a reviewed grant template issues the `workspace.knowledge.*` grants, and `agent_tools` on until the routes and the agent loop are on.
- **Tenant isolation**: composite tenant keys, FORCE RLS on all seven tables, tenant and actor only from `current_tenant()` or the entered lease; another tenant sees nothing (lab K3). Bodies never carry a tenant, tag, author, version or digest the server assigns.
- **Authority in code, outside prompts**: the human kernel decides `workspace.knowledge.approve` (`human_only`: execute writes and decides, administer deletes) and `workspace.notebook.write` administer (clear) before each definer, which rechecks under lock. A proposal grants nothing and changes no page; only a person's accept of its exact digest, at the page's version when it was made, makes a version (ADR-0024). The screen shows everything that digest covers before a person decides: the kind, title and text, the page it changes (its current title and opening) and the version it replaces, and every source; a page the person cannot open offers no decision, and one that changed since can only be declined (review F2). Agents never hold approve.
- **Per-viewer read tags** (ADR-0031 item 6): computed by SQL, never sent; lists, counts, search and direct reads filter per viewer (a hidden record is the same 404 as an absent one); a notebook is cleared only by someone who sees every entry, and only at the notebook revision their check read (`cmd_notebook_clear`'s `p_expected_revision`, compared under its lock; every entry written bumps it), so an entry written in between is a 409 conflict, never erased unseen (review F1). A run's reads hand back their content's tags (each search hit's, the brand voice page's), which the loop unions into the run's before its next call (`withResultTags`), so a note or proposal based on them carries them (review R1). A tag on a store with no current association (after "Disconnect store") is viewable by no one: a page whose every hidden tag is such a tag is stranded, named to a person who may delete knowledge (id, kind and version only) and deletable by them unseen; a page hidden by a tag on a linked store stays the same 404 for a deletion (review R2).
- **No customer data** (ADR-0031 item 2): a CHECK on every table refuses the customer tag; a run that read customer data cannot propose or write a note; typed text only, no uploads; the screen says so. NUL characters are refused in code before SQL.
- **Page text is data**: the brand voice enters a Listings turn only as one `ModelDataBlock` (source `knowledge_page`) after a fixed instruction; it never chooses tools (the release and context do), fields or products (checked in code, `product_mismatch`). Proposals record the run's `contextTaint`; the screen warns on `untrusted_external`.
- **Deletion before content** (ADR-0031 item 4): one transaction erases every version's text and sources, the search entry, pending proposals' text and the title, recorded in `knowledge_deletions` and the command log. A proposal is made under a share lock on its page, so none lands pending on a page deleted under it; one that did could still be declined (review R3).

## Review findings (AI review, separate context, same model family; 2026-10-24)

- **F1 (medium), a notebook cleared past what the clearer saw.** The work API read the live entries and checked each one's tags, then sent `cmd_notebook_clear`, which locked the notebook and erased every live entry with no expected revision. In READ COMMITTED an entry a run committed between the read and the lock was erased by someone who could not view it. Fix: the API reads the notebook's revision (`notebookRevision`) before the entries and passes it as `cmd_notebook_clear`'s new `p_expected_revision` (0047 changed in place: unapplied; manifest digest, tenant-conformance registry and probe updated). The definer compares it under its `FOR UPDATE` lock and answers `revision_conflict` (409, `recheck_before_retry`) when a write landed since. Tests: lab K10 (fails without the fix: 200 and the hidden entry erased `cleared`), and a static check in `tests/shop-knowledge.test.mjs` (lock, compare, erase; revision read before entries).
- **F2 (medium), accepting a suggestion bound content the screen never showed.** The digest covers the target page, its base version and the sources, but the row showed only the title, text, kind and "New page". Fix: `KnowledgeItemView` carries `sources` and `target`; the decoder keeps them, and `withKnowledgeTargets` joins each target with the same read's pages (the adapter and the fixture). The row shows the page it changes with the version it replaces, what that page says now (its opening), and every source with the note's full text; a page the person cannot open offers no decision, and a page that changed since can only be declined. Tests: the markup test in `tests/workspace-web-knowledge.test.mjs` (fails without the rendered details), the decoder and fixture cases, and lab K5 joining the real reply.

## Review findings (second AI review, separate context, same model family; 2026-10-25)

- **R1 (medium), the agent-side seam dropped its content's read tags.** `knowledgeSearchForRun` and `listingsBrandVoice` filtered on the page's tags and threw them away, so PR 11's loop could not add them to the run's, and a later `notebook.write` or `knowledge.propose` carried fewer tags than its source (a page with `orders.read` read back by a member without it). Fix: each `KnowledgeSearchHit` carries `readTags`; `listingsBrandVoice` returns `{blocks, readTags}` (the page's when it enters, [] otherwise); `withResultTags` (`@morrow/policy/knowledge`) is the loop's union, failing closed past 24 tags; the seam documents that the loop calls it before any later tool call. Tests: the unit case (hit and brand voice tags, the union into both tools' arguments), K6 (the brand voice's and a hit's tags equal the page's), K11 (an order-derived page accepted by R; a later run's hit carries `orders.read`, and its note and proposal store it; A never reads either back).
- **R2 (medium), "Disconnect store" stranded every page.** A tag on a store with no current association is viewable by no one, so the pages were hidden from everyone, `POST /knowledge/pages/:id/delete` answered 404 and the hidden brand voice made every new one 409. Fix: `knowledgeViewer` also names detached tags; `pageDelete` accepts a stranded page (every tag the person may not view is detached) for a person holding `workspace.knowledge.approve` `{administer}` on the workspace (decided first, as before); the pages read adds `disconnectedPages: [{id, kind, version}]` for such a person only ([] otherwise); the screen lists them under "From a disconnected store" with Delete only, and counts a stranded brand voice as the shop's one. A page hidden by a tag on a linked store stays the same 404 for a deletion. Tests: K13 (before: the order-derived page is 404 to A; after the disconnect: listed to A only, B and R told nothing and refused, a wrong version 409, the brand voice deleted and recorded, the order-derived page erased unseen, a new brand voice 201 with the null-store tag), the decoder and markup cases.
- **R3 (low), a proposal could land pending on a page deleted under it.** `run_knowledge_propose` read its target without a lock, and the deletion never took the proposals' lock. Fix: the target is read `FOR SHARE` (0047 changed in place: unapplied; manifest digest updated), so READ COMMITTED waits for an in-flight deletion or version and re-checks the row: `id_out_of_scope`, and the base is the committed version. Backstop: a decline of a proposal whose page was deleted proceeds (erasing its text); an accept of it is 404. Tests: K12 (the deletion's definer done but uncommitted, the propose waits on the page and is refused, nothing written; a seeded pending proposal on the deleted page is 404 to accept and declinable) and the static check of the lock.
- **R4 (low), a replayed notebook clear answered another shape.** The first answer was `{installationId, cleared: true}`, the recorded result `{installationId, entriesErased}`. Fix: the first answer is the definer's recorded result, as for every other knowledge command; `work-api.md` updated. Test: K7 (the first body `{installationId, entriesErased: 100}`, the replay the same plus `replayed: true`).
