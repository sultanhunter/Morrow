## Goal

A shop keeps what its agents should know (its brand voice, policies, product facts, suppliers and decisions) as typed pages with versions and sources. Agents suggest additions; a person accepts or declines each one. Each installed agent keeps its own notebook. Listings can write in the shop's brand voice, with the page entering its prompt only as marked data. A page and all its versions can be deleted before any real content exists.

## Security notes

- **Default off, fails closed.** `docs/decisions/shop-knowledge-staging.json` holds `switch` and `agent_tools` off. Every route answers 503 before body work or a connection; the screen's port methods are uncomposed and send nothing; the tools refuse `switch_off`; `listingsBrandVoice` reads nothing. `edge:check` refuses `switch` on until a reviewed grant template issues the `workspace.knowledge.*` grants, and `agent_tools` on until the routes and the agent loop are on.
- **Tenant isolation**: composite tenant keys, FORCE RLS on all seven tables, tenant and actor only from `current_tenant()` or the entered lease; another tenant sees nothing (lab K3). Bodies never carry a tenant, tag, author, version or digest the server assigns.
- **Authority in code, outside prompts**: the human kernel decides `workspace.knowledge.approve` (`human_only`: execute writes and decides, administer deletes) and `workspace.notebook.write` administer (clear) before each definer, which rechecks under lock. A proposal grants nothing and changes no page; only a person's accept of its exact digest, at the page's version when it was made, makes a version (ADR-0024). The screen shows everything that digest covers before a person decides: the kind, title and text, the page it changes (its current title and opening) and the version it replaces, and every source; a page the person cannot open offers no decision, and one that changed since can only be declined (review F2). Agents never hold approve.
- **Per-viewer read tags** (ADR-0031 item 6): computed by SQL, never sent; lists, counts, search and direct reads filter per viewer (a hidden record is the same 404 as an absent one); a page is versioned or deleted only at the version whose tags the work API checked (tags grow only with a version, and each definer compares that version under its lock), so a version accepted in between is a 409 conflict, never overwritten or erased unseen (review PR68-I1); a notebook is cleared only by someone who sees every entry, and only at the notebook revision their check read (`cmd_notebook_clear`'s `p_expected_revision`, compared under its lock; every entry written bumps it), so an entry written in between is a 409 conflict, never erased unseen (review F1). A run's reads hand back their content's tags (each search hit's, the brand voice page's), which the loop unions into the run's before its next call (`withResultTags`), so a note or proposal based on them carries them (review R1). A tag on a store with no current association (after "Disconnect store") is viewable by no one: a page whose every hidden tag is such a tag is stranded, named to a person who may delete knowledge (id, kind and version only) and deletable by them unseen; a page hidden by a tag on a linked store stays the same 404 for a deletion (review R2).
- **No customer data** (ADR-0031 item 2): a CHECK on every table refuses the customer tag; a run that read customer data cannot propose or write a note; typed text only, no uploads; the screen says so. NUL characters are refused in code before SQL.
- **Page text is data**: the brand voice enters a Listings turn only as one `ModelDataBlock` (source `knowledge_page`) after a fixed instruction; it never chooses tools (the release and context do), fields or products (checked in code, `product_mismatch`). Proposals record the run's `contextTaint`; the screen warns on `untrusted_external`.
- **Deletion before content** (ADR-0031 item 4): one transaction erases every version's text and sources, the search entry, pending proposals' text and the title, recorded in `knowledge_deletions` and the command log. A proposal is made under a share lock on its page, so none lands pending on a page deleted under it; one that did could still be declined (review R3).

## Review findings (AI review, separate context, same model family; 2026-10-24)

## Review findings (AI review, separate context, same model family, after integration with `main`; 2026-10-25)

- **PR68-I1 (low), a page versioned or deleted past the version whose tags were checked.** `pageVersion` (`POST /knowledge/pages/:pageId/versions`) and `pageDelete` (`POST /knowledge/pages/:pageId/delete`) read the page without a lock and checked its read tags, then sent the definer the client's `expectedVersion`, never compared with the version they checked. `cmd_knowledge_write` and `cmd_knowledge_delete` compare only that number with the page's current version under their `FOR UPDATE` lock, and check no tags. So a client that named the next version, while another person accepted an agent's proposal in between (a new version whose tags add one the client may not view, such as `orders.read` on the store), overwrote or erased content they could never see. This broke the rule "no blind deletion of content others can see"; it is F1's bug class, left open for pages. Low: it needs a hand-made version and a race, the screen always sends the version it showed, nothing is shown to the client, and the client could delete the page at the version before anyway. Fix: both handlers compare `body.expectedVersion` with the version they read (409 `revision_conflict` otherwise) and send the definer that version. A page's tags change only with its next version (`knowledge_page_guard`; `knowledge_version_put` grows them), so the definer's compare under its lock proves they are still the tags the API checked. No migration change. Tests: lab K14 (fails without the fix: 201 with version 3 written over the hidden version, and 200 with both versions erased), and a static check in `tests/shop-knowledge.test.mjs` (tags checked, then the version compared, then the definer sent the page's version and never the body's; each definer compares under its lock; the page guard ties a tag change to the next version).
