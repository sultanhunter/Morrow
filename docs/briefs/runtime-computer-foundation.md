## Goal

One closed door for every computer job, with every safety property proven on a deterministic fake before any E2B code exists (PR 8 adds the adapter, PR 9 qualifies it and switches it on). The switch is committed off; no real E2B call is possible from this PR.

## Scope

- **The port** (`apps/broker/src/runtime-provider.ts`): create one fresh sandbox (pinned template, internet off, the operation id as its only metadata, the profile's lifetime), write a file, run the profile's one command, read a file, look a sandbox up by its operation, kill. No connect, resume, pause, network, environment or template choice. Every operation answers a closed outcome and never throws; outcomes are never flattened (`not_found` is not `killed`; anything after a send is `unknown_effect` or `unknown`).
- **The gateway** (`apps/broker/src/runtime-gateway.ts`): `RuntimeBroker.runtimeExecute(lease, generation, RuntimeJob@1, budget)` and `runtimeSweep(budget)`. Order: the switch (`RUNTIME_UNAVAILABLE` before any input, database or provider access), the closed inputs, the send mark committed in SQL, one create never retried, the job, the kill always, the content-checked outputs. The sweep reconciles stale operations by their metadata, kills leftovers, never creates, and counts a sandbox as absent only on a qualified profile past its deadline plus the grace.
- **The profile and job** (`packages/policy/src/runtime-computer.ts`): `morrow.computer` v1 (900 s lifetime, one 120 s exec as `agent`, 2 vCPU, 1 GiB); RuntimeJob@1 checked by hand (a step key, a script, minimised extracts, declared outputs; no command, template, network, environment or limit); the extract kinds `products`, `stock` and Level 1 `order_aggregates` with fixed column allowlists (no customer field or id, order id, URL, shop domain or email; a cell holding one refuses the job); outputs only PNG (metadata chunks dropped), CSV (formula cells escaped) and XLSX (no macros, objects, links, remote formulas or cloud functions; zip tricks and bytes outside the listed entries refused).
- **The ledger** (migration 0043, `apps/broker/src/runtime-ledger.ts`): `morrow_vault.runtime_operations` (one row per sandbox, tenant-keyed, FORCE RLS, content-free), `runtime_holds`, `runtime_capacity`, the caps in SQL (`runtime_caps()`, drift-tested), and four definers for the broker's login only: `runtime_operation_begin` (the lease as for a model call, the run running under it, the release declaring `runtime.execution.use`, no active hold, the monthly budget, the platform concurrency, three per workspace, the worst case booked, the `sending` mark), `runtime_operation_created`, `runtime_operation_settle` and `runtime_operations_open` (the sweep's ids-only list). `runtime_hold_lift` is the owner's operator function, granted to nobody.
- **Money**: `morrow_billing.run_book_cost` admits the kind `sandbox_compute` (0038's function otherwise unchanged); each sandbox's worst case (US$0.03 at list rates) is booked on the run's vendor reservation before the create. Caps: US$10 a month (E2B's limit is US$20), 10 concurrent (half of Hobby's 20), 3 per workspace.
- **Authority**: the catalogue capability `runtime.execution.use` (`billable_job`, `agent_direct_write`, not review-required, provider dependency D17; v1.1-only bodies; its provider binding is Morrow's neutral runtime port, `morrow`, which now also names D17). The send mark admits a run only when its installation's published release declares it with `execute`.
- **The fake and the conformance suite**: `apps/broker/src/runtime-fake.ts` (deterministic, faults that may say what really happened on the provider's side, a record of everything a sandbox could observe) and `tests/fixtures/runtime-conformance.mjs`, which every adapter must pass (PR 8 runs it against the E2B adapter and its wire fixture).
- **The switch** (`docs/decisions/runtime-staging.json`, committed `off`, `admission: synthetic_only`): the broker var `MORROW_RUNTIME_SWITCH` (exactly `on` or `cleanup_only`) and `E2B_API_KEY` in the staging broker's `secrets.required`, both only while it is not off; `edge:check` refuses any mixed state (`EDGE_RUNTIME_SWITCH_MIXED`). `on` needs `qualified_on` and its live record, a committed file under `docs/evidence/live/` (a name alone is refused, by `edge:check` and the staging tools alike); `merchant` admission needs `on`.
- **Key placement**: `npm run staging:put-secret -- E2B_API_KEY` reads the owner's chmod-600 file `~/.config/morrow/staging/e2b-api-key` (written with `morrow_put`; format `e2b_` plus 20 to 128 letters and digits) and sends it to the broker only through `wrangler secret bulk` stdin, never argv. While the switch is off it refuses (`STAGING_RUNTIME_OFF`) before reading the file or running any tool, unless the owner passes `--while-runtime-off`. The broker then holds a key it never reads, and gate 6 and `secrets-status` accept it present or absent (`brokerOptionalSecretsFor`).

Non-goals: the E2B adapter, the template recipe and build command, the envd token's vault record, stops killing their scope's sandboxes and the scheduled sweep (PR 8); qualification and switching on (PR 9); uploads and agent computer tools (PR 13).

## Security notes

- **No credential or internet in the sandbox.** The create has no environment, network or template parameter; the fake records everything a guest could observe and the suite asserts that no key, token, URL or shop domain reaches it. E2B's envd token stays in the broker for one job (PR 8 moves it to a vault record destroyed at kill).
- **Minimised inputs** are checked cell by cell before the ledger; a URL, shop domain or email refuses the whole job, nothing is rewritten. The script goes into the guest as written, so it gets the same screen (in its NFKC form too): a URL, shop domain, workers.dev or R2 host, signed-URL marker or email address anywhere in it, a comment or string included, refuses the job with `input_content_forbidden` before the ledger or any create. The screen catches text, not intent: a script that assembles such a string at run time is not caught here, and the guest still has no internet, credential or store data beyond the minimised extracts.
- **XLSX outputs** are the only barrier between guest-written bytes and the owner's spreadsheet app, and the accepted bytes are served as written. So every byte belongs to an entry the central directory lists (the first local header at offset 0, each next one where the previous entry's data and data descriptor end, the last ending at the directory, no archive comment, and each local header agreeing with the directory on flags, method, name and sizes), and a reader that walks local headers finds no hidden entry. Every part is read, whatever its name: an image by its magic bytes, or strict UTF-8 XML. A character reference (other than tab, newline and carriage return), a CDATA section, a comment, a DTD or entity, a processing instruction, another encoding, duplicate attributes or a broken tag rejects the file (`xlsx_invalid`) instead of being decoded. In every part, formulas are found by local name whatever the namespace prefix (cells and charts, defined names, conditional formats, validations including x14's, table columns and pivot `formula` attributes) and a remote function (WEBSERVICE, HYPERLINK, IMAGE, RTD, DDE and the rest), a cloud function that sends cell contents out on recalculation (COPILOT, TRANSLATE, DETECTLANGUAGE, STOCKHISTORY, Python's PY), an OLAP cube query, an add-in's user-defined function (`_xludf.`, `_xldudf`), any `_xlfn.`/`_xlws.`-prefixed function outside a list of pure local calculations (so a cloud function Excel adds later fails closed), an external reference (`[`) or a DDE pipe (`|`) rejects it; every relationship is checked by mode (only `Internal`), target (no scheme, UNC or network path) and type (macro, object and link types), and a hyperlink with a relationship id rejects it (`xlsx_macro`, `xlsx_object`, `xlsx_link`).
- **Unknown outcomes**: the send mark commits in its own transaction before any create; a lost create, kill or lookup is `unknown_effect` with a runtime hold that blocks every create until a person lifts it (cleanup is never blocked); a replayed step never creates again; `not_found` alone never settles an operation.
- **Tenant isolation**: the ledger is tenant-keyed with FORCE RLS; the broker's login holds no table privilege and reaches it only through its definers; no other login executes them. The sweep's list is cross-tenant but ids only (ADR-0029's accepted residual).
- **Default deny**: switch off, no adapter composed in the deployed broker (`providers: {}`), no template pinned, `qualified: false`. Production has no switch.
- **Checks in code**: the caps, the hold, the capability and the booking are SQL, not prompts.
