## Goal

The E2B adapter behind PR 7's `RuntimeProviderPort`, composed only in the broker, with every safety property proven over a recorded-HTTP fake of E2B's documented API before any real call: the key stays a broker secret, the sandbox's envd token lives in the broker vault and dies with the sandbox, stops kill sandboxes, clean-up is never blocked, and a broken E2B reply holds the runtime until a person lifts it. Plus the template recipe the owner builds with the owner's own E2B login. No sandbox can be created yet: no template is pinned and nothing is qualified (PR 9).

## Scope

- **The adapter** (`apps/broker/src/runtime-e2b.ts`): hand-written `fetch` to two fixed origins, `https://api.e2b.app` (`X-API-Key`) and envd behind `https://sandbox.e2b.app` (`E2b-Sandbox-Id`, port 49983, `X-Access-Token`); no E2B SDK, no Node API, no host taken from a reply. Every request uses `redirect: "manual"`, and any redirect is a broken reply. Replies are read up to fixed bounds, every call is cut off at the caller's budget, and every method answers one closed outcome and never throws. Learned from E2B's public OpenAPI and docs with WebFetch, never by calling E2B.
  - **Create** `POST /v2/sandboxes` with exactly: the pinned template, `timeout` 900, `autoPause` false, `allow_internet_access` false, `network.allowPublicTraffic` false and `metadata {operation}`, plus an `Idempotency-Key` derived from the operation id. Never environment variables, MCP, IAM, volumes, auto-resume, connect, resume, pause, refresh or timeout changes. Only a well-formed `201` naming the pinned template, an envd version, an envd token and E2B's own domain is `created`. `429` is `quota_exhausted` and `402`/`403` is `billing_blocked`; both still leave the operation unknown with a hold. Every other answer after the send is `unknown_effect`; an undocumented status, a redirect or a malformed `201` is also marked `broken`.
  - **Status**: the list `GET /v2/sandboxes?metadata=operation=<id>&state=running,paused` (one page only), then, when the id is known, `GET /sandboxes/{id}`. Both reads must agree. **A lone 404 never means absence**: `not_found` needs E2B's own error body on the detail and an empty list. A paused sandbox, or one showing internet, pause on timeout or auto-resume, reads as `paused`, which the gateway kills at once.
  - **Kill** `DELETE /sandboxes/{id}`: only `204` is `killed`. A `404` with E2B's body is read back once and counts as `not_found` only if the detail says absent too. Anything else is `unknown`.
  - **envd**: `POST`/`GET /files` (octet-stream, the `agent` user, one of the profile's paths) and `process.Process/Start` (Connect JSON framing; the profile's one command as `agent`, no environment, no stdin, `Connect-Timeout-Ms` at the exec limit). A `deadline_exceeded` end, or the adapter's own stop 3 s past the timeout, is `timed_out`. A cut stream is `unknown`. A malformed frame, a refused token or an unexpected status is `unknown` marked `broken`.
- **`broken`** (`runtime-provider.ts`): an optional mark on the port's unknown outcomes. The gateway records such an operation `unknown_effect`/`reply_invalid` before its kill, so a runtime hold stays until a person lifts it (`morrow_work.runtime_hold_lift`), even when the kill then succeeds.
- **The envd token as a vault record** (migration 0047, `vault.ts`, `runtime-ledger.ts`, `runtime-gateway.ts`). `morrow_vault.credentials` admits the provider `e2b` with the kind `e2b_envd_token`, keyed by its operation id, version 1 only, with its own three destroy reasons (constraints keep E2B and Shopify rows apart; no table is added, so the vault keeps its two sealed-secret tables). The gateway seals the token from the create's reply straight into the record (`runtime_token_put`, once, only while the operation is `created`) before the job starts. It opens the record for each call to the sandbox (`runtime_token_get`). The trigger `morrow_work.runtime_token_end` destroys it in the same statement as any settlement (`sandbox_killed`, `sandbox_absent`, `sandbox_unknown`). The envelope's additional data binds the operation id.
- **Stops kill sandboxes** (ADR-0029 item 9). `runtime_token_get` reads the run's lease and stops as the sweep does. Once a stop (platform, connection or installation) covers the run, or its lease has ended or expired, it answers `stopped`, the job ends at its next call with the code `stopped`, and the gateway's own kill follows at once. `runtime_operations_sweep` replaces 0043's list in the broker's registry: the same ids-only rows plus `stopped`, so the sweep kills a stopped operation's sandbox without waiting for staleness, and leaves one it cannot see yet to a later pass (only a stale operation is ever recorded unknown or absent).
- **The clean-up job** (`apps/workers/src/runtime-sweep.ts`): every fifth minute of the orchestrator's existing one-minute cron, `RuntimeBroker.runtimeSweep` runs beside dispatch (kept alive by `waitUntil`), whatever the model-provider switch, dispatch, a stop or a hold says. It never creates. The broker's runtime switch decides: `off` answers `BROKER_HELD` before any database or provider access; `cleanup_only` and `on` sweep. It logs counts, never ids.
- **The template recipe** (`infra/e2b/morrow-computer/`): `e2b.Dockerfile` (Debian trixie-slim, Python with numpy, pandas, matplotlib, openpyxl and XlsxWriter from Debian's signed packages, no pip, browser, network tool, compiler or secret; the non-root user `agent` with its three directories; `Agg` charts), `template.json` (the build record, empty until the owner builds, with the recipe's SHA-256), and `README.md` with the exact commands the owner runs in their own Terminal with `@e2b/cli@2.22.3` and their own E2B login. Claude never builds it.
- **Composition** (`apps/broker/src/index.ts`): the deployed broker composes the E2B adapter and nothing else (the fake stays tests-only), with `template: e2bPinnedTemplate` (`null`) and `qualified: false`.

Non-goals: the recorded qualification and switching on (PR 9); agent computer tools and uploads (PR 13); any real E2B call, template build or key placement.

## Security notes

- **Key custody.** `E2B_API_KEY` binds only to the broker (`edge:check`: `EDGE_CREDENTIAL_BINDING_OUTSIDE_BROKER` and `EDGE_RUNTIME_SWITCH_MIXED`, unchanged from PR 7). `tests/runtime-e2b.test.mjs` proves that no file under `apps/` outside `apps/broker/src` names the key, E2B's origins or the adapter, and that only the broker's `index.ts` imports it. The key goes only to the platform API, the envd token only to envd, and neither reaches a request body, a guest, a result or a log.
- **Nothing a sandbox receives** holds a key, token, URL, shop domain, customer field or Morrow link: the create body is closed (no environment, no network, metadata only the operation id), and PR 7's conformance suite checks what the guest could observe over the wire fixture.
- **The envd token** never exists in the clear outside one call. The broker seals it with the vault keyring before the job, opens it per call, and wipes the plaintext buffer after each open. Any settlement destroys it in SQL. A token that cannot be stored or opened ends the job, and the sandbox is still killed.
- **Unknown outcomes.** PR 7's send mark still commits before the create, and the create is never retried. With the conservative defaults, every failure after a send is unknown. A lone 404 never counts as absence, and `not_found` alone never settles an operation (absence also needs a qualified profile past the grace, unchanged).
- **Holds.** A broken reply (a redirect, an undocumented status, a malformed body, a refused token) sets a runtime hold that only a person lifts, and so does an unknown create, kill or stale lookup (PR 7's rule: the sandbox may still exist). A plain unknown inside a job (a timeout or a 5xx on a file or the command) ends the job; its sandbox is then killed, and only a confirmed kill settles it without a hold. Clean-up is never blocked by a hold or a stop.
- **Tenant isolation.** The new definers run for `morrow_vault_broker` only and are registered in the tenant-conformance registry. The token row is tenant-keyed under the vault's FORCE RLS, and the sweep's list stays cross-tenant ids only (ADR-0029's accepted residual).
- **The template pin.** E2B's API documents no create by build id: a template id starts its newest ready build. So `template.json` records the build PR 9 qualifies, the README tells the owner never to rebuild outside a reviewed PR, and a new build voids the qualification (open question below).
- **Default deny.** The switch is off, the template is `null` and qualification is `false`. Production has no switch.
