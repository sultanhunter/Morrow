## Scope

**Migration 0058 (`morrow_work`, executes as `morrow_work_owner`)**, ADR-0041 item 4's table, minus the memory tables (H12a to H12c) and ADR-0040's conversation tables (P07.T03):

- **Platform rows** (FORCE RLS, read by the command role): `loop_catalogue_versions` (version 2, proposed: its digest and its safety template, AgentRunSafety@1 without the entry's `max_tokens`, in place of AgentRunCaps: no turn, call, question or wall-time column), `loop_catalogue_entries` (rates for metering, never a cap), `tool_catalogue_entries` (ToolCatalogue@1 version 4 with its family; the memory and harness tools grant nothing), `context_policy_versions` (ContextPolicy@1 version 1, proposed, its digest the SHA-256 of its RFC 8785 text, recomputed by a CHECK). Each is drift-tested against the generated data. Admission takes only active rows, so nothing is admitted until reviewed forward migrations publish them (version 2 with the owner's confirmation, after H3 rewrites it Opus-only).
- **Tenant tables** (22, composite tenant keys, FORCE RLS, the session and lease templates, no DELETE or TRUNCATE): `jobs`; `agent_contexts` (scope, one writer, pinned tools, system text, model, effort, renderer and context policy, read tags and taint that never shrink); `context_epochs` (kind, opening as references and digests, cut and tail, its own 90-day clock); `agent_runs` (kind and purpose; lineage: job, root, parent, parent tool use, call, depth 0 or 1, fork and continuation; context, conversation and `source_inbox_id`; segment, incarnation, `workflow_instance_id` = `<run>-s<segment>-i<incarnation>`, heartbeat; the job envelope's id, absolute expiry, renewal and active-time base; the current lease and renewals; the one open wait; RunTaint and read tags; `person_memory_loaded`; credits held, drawn, refunded and absorbed; the pinned manifest with harness, runner, renderer, tool catalogue, loop catalogue, context policy, rate card and safety profile versions and AgentRunSafety@1; counters as `bigint`; a closed `ended_reason`); `agent_calls`; `agent_run_questions`; `run_waits` (one open wait per run, its kind and typed condition, wake and lapse times, the resolution and its lease source); `context_checkpoints`; `run_turns` keyed `(org, ws, context_id, sequence)` with `run_id`, `turn` (1 to 100,000) and `attempt` as columns, `UNIQUE (run_id, turn, attempt)`, epoch, purpose and notices, and no `final`; `run_tool_calls` (a stable label `c<n>` per context); `agent_model_calls` (purpose, epoch, cache TTL, section tokens, one open call per run and purpose, credits held and drawn); `run_plans` and `run_plan_revisions`; `run_events` (content-free, numbered per root run); `teammate_results`, `result_items`, `result_item_pages`; `run_detector_state`, `run_segments`, `run_taint_sources`, `run_memory_reads`, `upkeep_triggers` (at most one pending or running per notebook or thread).
- **CHECKs are safety ranges only**: turns 1 to 100,000; tool calls per turn 1 to 64 (ordinals 0 to 63, at most 64 `tool_use` blocks in a reply); `max_output_tokens` up to 128,000; call budgets up to 1,800,000 ms; a wait on a person 1 to 365 days; a stored user message 384 KiB (ContextPolicy@1's `storedMessageBytes`); a reply its own 4 MiB of jsonb text, twice H6's `replyStoredBytes` (2 MiB of compact JSON; H6's carry-forward N3). No column or definer is a turn, call, question, time or money limit; the old limit end reasons stay in the enum for old records only, and no definer writes one.
- **Definers.** A person's acts (the api): `cmd_agent_run_admit` and `cmd_agent_run_answer`. The runtime's ids-only definers, each one call and executable only by `morrow_runtime_executor`: `agent_run_lease_renew`, `agent_run_resume`, `admit_upkeep_run`, `agent_run_wake_candidates`, `agent_run_segment_roll`; and the Workflow's entry lookups `agent_run_pending_starts`, `agent_run_resume_lease`, `agent_run_start` (same shapes as PR 11's). Owner helpers: `agent_run_event` (RunEvent@1 under the root's lock), `agent_run_admission_check` (admission's checks again for an admitted run), `agent_run_end` (an open model call closes uncertain, the open wait and question close, the envelope and hop are revoked, the job ends when no run of it is open, the context stays open). The command role's helpers: `agent_run_entered` (the entered run lease's run, locked) and `agent_lease_issuable` (the check of the one new `work_leases` policy, `lease_agent_issue`).
- **`source_inbox_id` and `conversation_id` land without their foreign keys**: P07.T03's conversations, messages and `conversation_inbox` have not landed (plan row H4). A forward migration adds them once they exist.
- **Credits** (ADR-0039 PR 3; ADR-0041 item 9): the run's and each model call's credit columns, in whole credits. H8 fills them under the wallet's row lock; admission holds nothing, and the switch's `shared_wallet` prerequisite keeps it off until H8.

- **The broker's fence and turn call** (H7c): `morrow_vault.agent_turn_begin` and `agent_turn_end` are not created; the gateway still takes the whole-conversation turn call, which is not H6's ids-only ModelCall@2, and its replies carry no section tokens, so they are not valid ModelResult@2 replies (both pinned in `broker-agent-turn.test.mjs`). - **The conversation's shape** (H7b and H7d): tool results without their `c<n>` labels and item ids (not H6's UserModelMessage), the 8 KiB result bound in place of the 24,000-token inline bound with offload to result items, answers as text blocks in place of post blocks.
- **The orchestrator's agent-run start** (H7b): the cron starts or wakes an agent run as segment 1, incarnation 1 (`<run>-s1-i1`, ADR-0041 item 6's id) with the `agent-run-answer` event; the Workflow body refuses any other segment or incarnation. A renewal lease of a running run is listed by `agent_run_pending_starts` with `resume` true, so this cron would send it the answer event; H7b's wake events (`w-<waitSeq>`), segment rolls and sweep replace this start.
- **The sweep's actions** (H7b): `agent_run_wake_candidates` lists `resume`, `check_in`, `lapse`, `close_lapsed` and `wake`; the definers that check a run in, lapse its wait (`person_wait_expired`, `checkin_unanswered`) and close a lapsed lease (`lease_lapsed`) are H7b's.
- **Continue** (H7b and H11b): only the requester's answer renews the job envelope in this PR; Continue after a check-in or a close is H7b's.
- **Other lease sources**: a mandate episode (ADR-0024's mandate packet), child, fork and review admission (H10, H11), standing-request firing (H17). No definer admits those runs, and no login can write a run, call or wait.
- **Upkeep's view check** (H12a to H12c): `admit_upkeep_run` re-checks the requester's membership, stops, the installation, its release and the store; the requester's live view of the notebook or thread it tends (ADR-0041 items 25 and 27) is decided by H12's code, which writes the trigger and reads the memory under the kernel at each read.
- **Detectors and check-ins** (H7b): `run_detector_state` and the safety profile's values exist; nothing evaluates them yet.
- **Content clocks and deletion** (H7d, G9, H9d): content rows' `expires_at` is set when their epoch closes (H7d); each new run-content class gets its deletion handler in the PR that first writes it; H9d registers the classes that may hold a customer's name.
- **Loop catalogue version 2's values** (H3): still Haiku, Sonnet and Opus 5.5 at `low`, `medium` and `high` with 5,000, 12,000 and 16,000 `max_tokens`, as generated on `main`; H3 rewrites it Opus-only at 32,000 and 64,000 while it is proposed, and this migration's row follows by drift test.

## Security notes

- **Tenant isolation.** Every new table is FORCE RLS with composite tenant keys and the maintenance-only owner policy. A person's acts write in the session context (`tenant_command`), the runtime's definers under the entered run lease (`tenant_lease`). The runtime login's cross-tenant reads are SELECT-only, ids and codes of open rows: open runs (`runtime_agent_open`), open waits (`runtime_wait_open`), pending or admitted upkeep triggers (`runtime_upkeep_read`). The api reads its tenant's runs and jobs column by column: no manifest text, lease, envelope, hop, wait, taint, read tags, safety profile, digest, request or command. No login holds a table privilege on the new tables beyond the command role's (a forged insert is denied: lab M1, C1, F1). Tenants and runs come from `current_tenant()` or the entered lease, never from a caller, except the two definers that name their tenant (`agent_run_resume`, `admit_upkeep_run`), which run only as the runtime login, outside any session or lease, and then enter the run's own lease.
- **A lease grants nothing** (ADR-0041 item 7). It selects the tenant and fences generations; the kernel decides every tool call at call time (H7b keeps PR 11's per-call decision). The one new `work_leases` policy, `lease_agent_issue`, lets the runtime's definers insert only three run leases, each for exactly its run's (or trigger's) requester, store, connection and installation: a renewal of the entered lease of the same queued or running run (`<run>:l<n>`), a resolvable wait's resume (`<run>:w<sequence>`, never a question wait), or one pending upkeep trigger's run (`<run>:u:<trigger>`).
- **Renewal and resume re-run admission's checks** (`agent_run_admission_check`): the requester's live membership, the job envelope's absolute expiry (7 days or 24 hours active), stops on the store and installation (platform stops included, under lease_open's interlock), the installation active on its store and connection with its release published, the store's association, a routed run's tasks open and its delegation envelope and hop neither revoked nor expired. Past the envelope, renewal checks the run in (a check-in wait; only the requester's act renews an envelope) and resume refuses with no write; a wait past its lapse time never resumes (ADR-0041 item 9: a job parked 7 days closes, and only Continue goes on); any other failure ends the run with its reason. A superseded segment or incarnation writes nothing. This is ADR-0041 item 7's accepted residual (OD-2026-10-26-7, question 2): a compromised orchestrator can keep an admitted job acting, and resume its resolvable waits, within the requester's live grants until the envelope expires, and no further.
- **Approvals, gateway, unknown outcomes.** Nothing here approves, applies or sends. `agent_run_end` closes an open model call `uncertain` and never as success; H8 settles its credits.
- **Permission and budget checks outside prompts.** No money cap, and no turn, call, question or time limit, in SQL or code (ADR-0039; ADR-0041 item 3; OD-2026-10-26-12); the safety profile's check-ins park and ask a person (H7b). Credits are the only budget, held by H8; until then `shared_wallet` keeps the switch off.
- **Content.** Content lives only in `run_turns`, `context_checkpoints`, `run_plan_revisions`, `teammate_results`, `result_items` and their pages, and `agent_run_questions` (registry class `workspace`); every other table holds ids, codes, counts, digests and times, and `run_events` holds no JSON at all. Derived content rows carry read tags, an audience, source subjects and taint (ADR-0041 item 25). No tool that reads a store's content is composed, and no customer data can enter before P09.T05's path (the switch's `store_content_cleanup` prerequisite; H9a's screen; H9d's registration).
- **Default deny.** The switch is committed off with six prerequisites, `harness_runner` among them; catalogue version 2 and context policy version 1 are committed proposed, so SQL admits nothing even with the switch on.
- **Immutable migrations.** 0058 is applied nowhere; 0001 to 0056 are untouched.

| `admit_mandate_run` from one trigger row | M1 not built for agent runs: no such definer, and no login writes a run. |
| Child, fork and review admission | C1 not built (H10, H11): no definer, and no login writes a call. |
| Per-step renewal (`agent_run_lease_renew`) | R1 a turn step renews to `<run>:l1` and releases the entered lease, another step with time left is current, another incarnation is superseded and writes nothing; R2 past the envelope the run checks in (a 7-day check-in wait, its lease released); R3 a failed admission check (a disabled installation) ends the run `lease_ended`, revoking its envelope and hop and ending its job; R4 after a revoke no lease can be entered to renew. |
| Wait resolution (`agent_run_resume`) | W1 a due timer resumes under `<run>:w<n>` after admission's checks; W2 a resolvable wait resumes, a question wait is the requester's only; W3 past the envelope it is refused with no write; W4 under a stop nothing persists; W5 a wait past its lapse time (a credits wait parked over 7 days, covered since) never resumes and writes nothing. |
| Upkeep admission (`admit_upkeep_run`) | U1 one pending trigger admits one upkeep run with the upkeep tools, again answers `admitted_before`, a second pending trigger for the same notebook is refused; U2 the SQL-built manifest is RFC 8785 and a valid AgentRunManifest@1 with the digest code computes; U3 a revoked requester admits nothing; U4 a disabled installation skips the trigger. |
| Standing-request firing | F1 not built (H17): no definer, no table. |
| The sweep | S1 `agent_run_wake_candidates` lists ids, positions and one action each (`check_in`, `resume`, `lapse` for a lapsed question and a lapsed resolvable wait, `close_lapsed`) and issues no lease; S2 a segment roll records `<run>-s2-i1`, replays safely, and another incarnation is superseded. |

And the data model: D1 the CHECKs are safety ranges, each just inside and just outside (turns, tool calls per turn, `max_output_tokens`, call budgets, person waits, the reply's stored size); D2 FORCE RLS on every table, no DELETE, an append-only event stream and the api's column reads; D3 the event stream holds ids and codes only.
