## Goal (observable product delta)

**Today:** a non-superuser administrator cannot apply the chain (0005 stops it), and every hosted identity login would be denied twice: by the database guards and by the adapters' `role_member` preflight.

**After:** the chain applies end to end as a Neon-shaped `neondb_owner` in CI. The hosted membership shape passes every executor guard, and every other membership shape is still denied. 0001–0004 and the prerequisite files are byte-identical. The exception to "applied migrations are immutable" is recorded, bounded by a test, and closes at the first persistent apply.

## Design

### D1 The recorded administrator (0005, right after `BEGIN;`)

```sql
CREATE TABLE morrow_identity.migration_administrator(singleton boolean PRIMARY KEY DEFAULT true CHECK(singleton),
 role_oid oid NOT NULL, role_name name NOT NULL, recorded_at timestamptz NOT NULL DEFAULT statement_timestamp());
INSERT INTO morrow_identity.migration_administrator(role_oid,role_name) SELECT r.oid,r.rolname FROM pg_catalog.pg_roles r
 WHERE r.rolname=session_user AND r.rolcanlogin AND (r.rolsuper OR r.rolcreaterole) AND r.rolname NOT LIKE 'morrow\_%';
-- preserve_migration_administrator() raises MIGRATION_ADMINISTRATOR_IMMUTABLE from ONE statement-level
-- BEFORE INSERT OR UPDATE OR DELETE OR TRUNCATE trigger; REVOKE ALL FROM PUBLIC; ENABLE and FORCE RLS;
-- CREATE POLICY identity_owner ... FOR SELECT TO morrow_identity_owner USING(true). No write policy.
CREATE FUNCTION morrow_identity.recorded_administrator() RETURNS oid
LANGUAGE sql STABLE SECURITY DEFINER SET search_path=pg_catalog,morrow_identity,pg_temp AS $$
 SELECT r.oid FROM morrow_identity.migration_administrator a
 JOIN pg_catalog.pg_roles r ON r.oid=a.role_oid AND r.rolname=a.role_name
 WHERE a.singleton AND r.rolname NOT LIKE 'morrow\_%' AND (SELECT count(*) FROM morrow_identity.migration_administrator)=1
 AND NOT EXISTS(SELECT 1 FROM pg_catalog.pg_auth_members x WHERE x.roleid=r.oid) $$;
```

A DO block then raises `MIGRATION_ADMINISTRATOR_INVALID` unless `current_user` is the identity owner, `recorded_administrator()` is not NULL, and its name equals `session_user`.

### D2 The closed membership set (0005, after D1)

```sql
CREATE FUNCTION morrow_identity.memberships_closed(p_role name) RETURNS boolean
LANGUAGE sql STABLE SET search_path=pg_catalog,morrow_identity,pg_temp AS $$
 SELECT COALESCE((SELECT NOT EXISTS(SELECT 1 FROM pg_catalog.pg_auth_members m
   JOIN pg_catalog.pg_roles g ON g.oid=m.roleid JOIN pg_catalog.pg_roles u ON u.oid=m.member
   WHERE (m.roleid=t.oid OR m.member=t.oid) AND (
     (m.roleid=t.oid AND m.member=a.oid AND NOT a.rolsuper AND m.grantor=10::oid           -- (A) creation row
      AND m.admin_option AND NOT m.inherit_option AND NOT m.set_option)
  OR ((g.rolname,u.rolname) IN (('morrow_work_api','morrow_api_worker'),('morrow_work_command','morrow_work_owner'))
      AND m.grantor=a.oid AND NOT m.admin_option AND NOT m.inherit_option AND m.set_option) -- (B) reviewed
  OR (m.roleid=t.oid AND m.member=a.oid AND NOT a.rolsuper AND m.grantor=a.oid             -- (C) runner, in-run
      AND NOT m.admin_option AND NOT m.inherit_option AND m.set_option
      AND g.rolname IN ('morrow_identity_owner','morrow_work_owner')
      AND g.rolname=current_user AND u.rolname=session_user)) IS NOT TRUE)
  FROM pg_catalog.pg_roles t, pg_catalog.pg_roles a
  WHERE t.rolname=p_role AND a.oid=morrow_identity.recorded_administrator()),false) $$;
```

**The two other helpers.**
- `morrow_memberships_closed()`: `recorded_administrator() IS NOT NULL` and `memberships_closed(r.rolname)` for every role `LIKE 'morrow\_%'`.
- `executor_memberships_closed(p_executor name)`: `memberships_closed(p_executor) AND memberships_closed('morrow_identity_owner')`.

**Grants.**
- All five functions are owned by `morrow_identity_owner`, with `REVOKE ALL ... FROM PUBLIC`. No executor gets EXECUTE.
- 0014 grants EXECUTE on `recorded_administrator()`, `memberships_closed(name)` and `morrow_memberships_closed()` to `morrow_work_owner` only, for 0015.

**Why each rule is exact.**
- **(A)** is what PostgreSQL writes. It cannot be created by anyone but CREATE ROLE or the bootstrap superuser. The unique key (roleid, member, grantor) allows at most one per role.
- **(B)** is P06.T01a's reviewed pair, now bound to its grantor.
- **(C)** follows from session state, never a parameter. Because D4 commits the grant and the revoke together, (C) rows never persist.

### D4 Runner contract (for P04.T01i PR-B; amends its D3 steps 3–4)

**Prerequisites.** They run as the administrator, with `SET createrole_self_grant=''` and no SET ROLE.

**Each manifest entry is one transaction on one fresh connection:**

```sql
BEGIN; GRANT <executeAs> TO neondb_owner WITH ADMIN FALSE, INHERIT FALSE, SET TRUE; SET LOCAL ROLE <executeAs>;
<file without its first "BEGIN;" and last "COMMIT;" lines>
RESET ROLE; REVOKE <executeAs> FROM neondb_owner GRANTED BY neondb_owner; INSERT INTO morrow_migrations.applied …; COMMIT;
```

**After each commit.** The runner asserts from the catalog that no SET row names a Morrow role (`MIGRATION_SET_ROW_PERSISTED`). It never relies on REVOKE's exit status.

**Unknown outcomes** are settled by reading the ledger (P04.T01i). The grant and the revoke share the migration's fate, so no failure can leave a SET row behind.

**Step (4) "revoke the SET rows"** becomes the catalog assertion alone.

### D5 Application preflight

The eight adapters, and the literal copies in the two pgwire oracles, replace their `role_member` expression with this one:

```sql
(EXISTS(SELECT 1 FROM pg_catalog.pg_auth_members m WHERE m.member=r.oid)
 OR (SELECT count(*) FROM pg_catalog.pg_auth_members m WHERE m.roleid=r.oid)>1
 OR EXISTS(SELECT 1 FROM pg_catalog.pg_auth_members m JOIN pg_catalog.pg_roles u ON u.oid=m.member WHERE m.roleid=r.oid
   AND NOT (m.grantor=10 AND m.admin_option AND NOT m.inherit_option AND NOT m.set_option
   AND u.rolname NOT LIKE 'morrow\_%' AND NOT u.rolsuper))) AS role_member
```

**What stays the same.** The result keys and `requireRole` are unchanged, and `role_member: true` still throws `INVALID_INTERNAL_ROLE`.

**Defence in depth only.** The executor cannot read the record, so the database guard (D3) remains the authority. The adapter refuses a second administrator only by count, and every other non-creation shape by its form.

- [ ] (A) matches the recorded administrator's oid and name, grantor oid 10, and admin true, inherit false, set false exactly. There is no name-based grantor and no "any non-Morrow member".
- [ ] (B) is bound to the two named pairs and to the administrator as grantor. (C) depends on `session_user` and `current_user`, on the two `executeAs` roles only, and on no caller-supplied role or option.
- [ ] Every path fails closed: a missing record, a missing role, NULL (`COALESCE` and `IS NOT TRUE`), a renamed or dropped administrator, a member of the administrator, or a superuser administrator.
- [ ] The record is a singleton, owner-only, FORCE RLS with a SELECT policy only, and refuses writes through a statement-level trigger. The definer has a fixed `search_path`.
- [ ] Run-time guards keep every other conjunct byte-identical, and additionally require the identity owner to be closed.
- [ ] D4 commits the grant and the revoke in the migration's transaction. The runner verifies from the catalog. `createrole_self_grant` is forced to `''`.
- [ ] The application preflight is never weaker than "one creation-shaped row with a non-Morrow member", and the database guard stays authoritative.

## Self-critique (attacker review, 2026-10-19) and tightenings applied

1. **A second administrator.** The old 0015 rule accepted any non-Morrow (admin true, inherit false, set false) row from any grantor. Now (A) requires member = the recorded oid and grantor = oid 10, and the unique key allows at most one such row. A second CREATEROLE role's row on any Morrow role is denied (N1, N2), and a second applier at 0005 fails (AC09).
2. **A creation row with inherit or set.** The options are exact (N3, N4). The `createrole_self_grant` extra row is denied (N13), and D4 forces `''`.
3. **A different grantor.** Grantor checks use oid 10, not a role name (Neon's is `cloud_admin`). The administrator's self-granted copies are denied (N5).
4. **Rows added later.** Every guard reads the catalog live. Run time also covers the identity owner, which catches a leftover SET row (N6). Apply time covers every `morrow_*` role at 0005, 0014 and 0015. S5 and the runner check at rest. Only CREATE ROLE or the provider's superuser can create an (A)-shaped row.
5. **NULL and absence.** `COALESCE(..., false)` and `IS NOT TRUE` make an unknown, a missing record or a missing role deny (N10).
6. **Record tampering.** A row-level trigger was measured to let writes pass silently under FORCE RLS, so D1 uses a statement-level trigger. Binding to oid plus name defeats drop-and-recreate. Disabling the trigger needs the owner role, which only the trust root can reach.
7. **A wider trust root.** A role that is a member of the administrator could use its ADMIN option; that is denied (N9). A superuser administrator disables (A) and (C) (N11).
8. **(C) leaking to run time.** (C) needs `session_user` = the administrator, which no executor login can be. D4 never commits a SET row. (C) applies only to the two `executeAs` owners while they are `current_user`.
9. **The adapter gap.** The structural preflight cannot see the record. It refuses more than one row, any membership the executor holds, and Morrow or superuser members. The database guard decides everything else.
10. **Residuals accepted in ADR-0020.** The administrator and Neon's superuser are trust roots. The work run-time path reads no memberships (N12 is caught at apply time and by S5). Cross-cluster restore fails closed until P04.T04 designs a re-record step.
