# P03.T04f CI cost reduction

- **Task.** A lettered child of P03.T04 *Delivery controls*, after P03.T04e. Plan R1, Package 03, P03.T04f bullet.
- **Status.** Implemented on `claude/p03-t04f-ci-efficiency` from `main` `f8314e8`. The branch is pushed without a pull request, because a pull request starts a hosted run and the Actions minutes for October are nearly spent. Locally, `npm run ci`, `smoke:scaffold` and the Workers, `pg-core` and `pg-http` lab groups pass; `pg-linking` and `pg-work`, whose sources this packet does not change, failed on a heavily loaded host and failed the same way on `origin/main` (see Acceptance). A Tier 2 AI review (separate context, same model family) ran on the pushed branch, and its findings are addressed. Hosted CI and owner question OQ-1 are open, and **OQ-1 blocks the merge**.
- **Classification.** Mostly routine under ADR-0002: CI and harness work, plus a test-fixture fix. It changes no migration, contract, role, provider, deployment or spending. The exception is the two light paths (change 3 and the light push in change 1). They change what the required `foundation` gate accepts, and ADR-0014 item 4 says the aggregator "treats a skipped job as a failure". Gates are Material (ADR-0002), so these paths need an owner-approved ADR-0014 amendment before this packet merges (OQ-1).
- **Deviation from the brief.** The brief asked for a workflow-level `paths-ignore` for Markdown-only pull requests. This packet uses an in-workflow `scope` job instead (change 3 says why), so a docs-only pull request costs about 6 to 7 billed minutes rather than none. The pull request description must state this deviation so the requester can acknowledge it.

## Problem

GitHub Free gives this private repository 2,000 Linux Actions minutes a month. On 2026-10-19 about 1,842 of them were spent (111 runs, 506 jobs). GitHub bills each job's run time rounded up to a whole minute. Each of the 12 jobs repeats checkout, setup-node and `npm ci` (about 20 s, plus about 10 s for the image pull), and on average another half minute goes to rounding.

The pull request run on the P14.T01a PR-1 head (run 39171176579) took 36 minutes of job time and billed 43 minutes. Its job times were: `static` 1:48, `unit` 1:25 and 1:30, `workers-api` 2:58, `workers` 3:07, `pg-core` 4:16, `pg-linking` 5:18, `pg-http` 4:24, `pg-work` 4:50, `pgwire` 3:11, `ui` 3:25 and `foundation` 0:02. The push run after each merge repeated all of it.

## Changes

1. **A push to `main` that merges a checked head unchanged runs only `checks`.** `checks` holds the static checks (`npm run ci:static`) and the unit tests (`npm test`).
   - The full matrix on push used to repeat a run that had already passed. ADR-0014 item 1 requires a green `foundation` on the exact pull request head before merge. No written rule requires that head to contain the latest `main`, though, and pull request runs check out the head, not GitHub's merge ref.
   - So `scope` now also runs on push and checks the premise instead of assuming it. It sets `full=false` only when the pushed commit has a second parent whose tree is identical (`git diff --quiet <sha>^2 <sha>`). The merged tree is then exactly the head that item 1 required to be green.
   - A squash merge, a head that lacked the latest `main`, a direct push or an unreadable commit runs the full matrix. Every merge on `main` from `80b6897` to `f8314e8` would have run light: each merged tree equals its pull request head.
   - A new `workflow_dispatch` trigger runs the full matrix by hand on `main` or any branch. The concurrency group now includes the event name, so a merge push does not cancel a manual run.
2. **Fewer jobs, the same coverage.**
   - `static` and both `unit` shards become one `checks` job. It runs `npm test` first, on the clean checkout the shards used, then `ci:static`. The `test:shard` npm script is removed; the runner keeps `--shard`.
   - `workers-api` joins `workers`, as a step after the network-none container step.
   - The `postgres` matrix becomes three legs: `core-http` (the engine record, then `lab:group:pg-core` and `lab:group:pg-http`), `linking` and `work`. The timeout is 14 minutes.
   - `pgwire` and `ui` stay separate: `pgwire` is environment-specific and the flakiest, and `ui` alone installs Chromium.
   - Nine jobs remain instead of 12. `fail-fast: false`, the clean-tree gate, the scan before upload, the pinned action SHAs, the `foundation` name and `contents: read` are unchanged.
3. **Markdown-only pull requests run light.**
   - The `scope` job checks out the head with full history. On a pull request it sets `full=false` only when every file in `git diff --name-only --no-renames base...head` ends in `.md`.
   - The lab jobs need `scope` and run only when `full=true`. `checks` always runs, so `plan:check`, the rest of `verify`, the repository secret scan and the unit tests that read Markdown still run.
   - `docs/**` is not excluded: it holds 39 JSON files that code reads (contract schemas, provider decisions, design tokens, the task inventory, lab fixtures).
   - There is deliberately no workflow-level `paths` filter. GitHub reports nothing for a workflow it did not start. A required `foundation` then stays "Expected", which blocks the merge under branch protection, and ADR-0014 item 1 has no green check to rely on. `foundation` now runs on every event (`docs/development/ci.md`, Required check).
4. **The pgwire concurrent-callback hold.**
   - **What was observed.** The `controlled-neon-postgresql.json` reports downloaded from runs 39165441837 and 39120797236 both held at stage `concurrent_independent_callbacks` with no failed check. The error that rejected the lab's engine callback was therefore not a check, and the engine wrapper (`scripts/fixtures/controlled-neon-postgresql.mjs`) keeps only `primaryExecutionHeld`. So neither report says what failed.
   - **The missing await (fixed).** The fixture Worker returned `current!.auth.fetch(request)` without `await`, so a rejection from the login bridge escaped the fixture's `try`/`catch`. A local Miniflare 4.20260730 check with the lab's options confirmed this: unawaited, a rejecting handler answers 500 with Miniflare's error page; awaited, the fixture's own 503. The fixture now awaits the bridge. A held request returns a 503 JSON body that describes the failure: its name, a printable message of at most 300 characters with the fixture passwords removed, and a short code. It never includes the stack.
   - **The diagnosis (added).** The lab records each unexpected fixture response, with the fixture's description, in a new `dispatchFailures` list. It records any error that rejects its engine callback in `failure.error`: a rejected dispatch, an oracle or cookie-jar assertion, or a check. For such an error it also keeps the login flow it came from (`flowSerial`; `start` and `finish` mark their errors, because the concurrent stage runs two flows at once) and its first five stack frames inside the repository, as `path:line:column`.
   - **Redaction.** The fixture sends the whole message, with only its passwords removed. The lab removes every private marker from the whole text, and only then makes it printable and cuts it to 300 characters. A marker cut in half by an earlier cut could otherwise slip past both the redaction and the report's exact-match private-marker check, which still runs.
   - **The job log.** On a hold the lab prints one `CONTROLLED_PG_FAILURE:` line. It has the stage, error class names, fixture codes, flow serials, repository frames, request labels and statuses, but no message text, because the job log is never secret-scanned. The messages stay in the report, which `scan-artifacts.mjs` scans before upload.
   - No check or assertion changed.
   - **Not yet known.** The same local check shows that an escaped bridge rejection would have failed the recorded check `actual_84_callback_delivery_<n>` (a 500, not a 303). The two hosted holds therefore came from a different, non-check error. The next hosted hold names it, and the fix follows as a routine change. Until then this change is diagnosis, not a fix of the flake.

## Acceptance

- **P03.T04f-AC01 Event scope.** `ci.yml` triggers on `pull_request`, push to `main` and `workflow_dispatch`, with no path filter. `scope` and `checks` have no `needs` and no `if`, so both run on every event. Every other report-writing job needs `scope` and runs only on `full == 'true'`.
- **P03.T04f-AC02 Aggregator.** `foundation` runs on every event and needs every job. Its `LABS` list names every lab job, and its script counts exactly that many results. It passes only when `scope` and `checks` succeeded, and either every lab job succeeded on a full run, or every lab job was skipped on a light run (`full=false` on a pull request or a push). `tests/ci-workflow.test.mjs` runs its script with `bash -e` over 53 combinations of event and results. These include an unexpected or blank result at each position of `LABS`, all-blank results shaped as the real expression yields them, and one result too few or too many.
- **P03.T04f-AC03 Scope decision.** The `scope` script runs against a temporary git repository.
  - Pull requests. These give `full=false`: Markdown only, Markdown deleted, and a branch whose base has since moved. These give `full=true`: code, JSON under `docs/`, mixed changes, `.md` renamed to `.txt`, code renamed to `.md`, a `.md.json` file and an empty diff. An unreadable diff fails the job and writes no output.
  - `workflow_dispatch` gives `full=true`.
  - Pushes. A `--no-ff` merge of an up-to-date head, or of a head that already contained a moved `main`, gives `full=false`. These give `full=true`: a merge of a code head or of a Markdown-only head into a `main` that moved on, a single-parent commit, the root commit and an unknown commit.
- **P03.T04f-AC04 Coverage.** In a full run, every `lab:*` script runs exactly once, all of them from gated jobs. A light run reaches `format:check`, `typecheck`, `verify`, `plan:check`, `verify:delivery`, the build, `smoke:scaffold` and `npm test`, and no `lab:*` or `ui:*` script. `npm test` runs once, in `checks`, and its plan lists every top-level test file.
  - No repository source file that a gated job can load names a `.md` file. The walk starts from the files the gated npm scripts name, every Worker `main` and the SPA entries. It follows relative and `@morrow/*` imports, plus string literals that name repository source files.
  - Planting a Markdown read in `scripts/local-postgres-lab.mjs`, `packages/identity/src/neon.ts` or `apps/broker/src/index.ts` fails the test.
- **P03.T04f-AC05 Hardening kept.** The existing workflow tests pass unchanged in substance: pinned actions, uncredentialed head checkouts, scan-gated uploads, the step order, the clean-tree gate, `fail-fast: false` and the timeouts. Every report-writing job uploads exactly once and fails on an empty upload.
- **P03.T04f-AC06 pgwire diagnosis.** The fixture awaits the bridge and the held envelope carries the described failure. `dispatchFailures` and `failure.error` (message, `flowSerial`, repository frames) are in the report, and the private-marker check is unchanged. The log line carries no message text. Local evidence:
  - The lab's helpers, extracted and run in Node, behave as described. A marker that straddles character 300 of a fixture message comes out as `[private]`. An error marked with flow 3 is described with `flowSerial: 3` and a repository-relative frame. The log line keeps only class names, codes, flows, frames, labels and statuses.
  - `npm run typecheck` passes (the fixture is in its list).
  - The fixture bundled with the lab's esbuild options and run in Miniflare answers 503 with `{"held":true,"failure":{"name":"Error","message":"CONTROLLED_NEON_REAL_PG_WORKER_HELD","code":null}}` when nothing is initialized.
  - A minimal Worker confirms the escape: unawaited 500, awaited 503.
  - The hosted `pgwire` job is the authority, because the PG-wire labs refuse to run on macOS.
- **P03.T04f-AC07 Hosted cost and time.** The first hosted runs should show about 39 to 42 billed minutes per full pull request run, about 6 to 7 per push to `main` that merges an up-to-date head, and about 6 to 7 per Markdown-only pull request. `postgres (core-http)` should take at most about 8 minutes, and the pull request should take under 10 minutes from trigger to `foundation`. ## Owner questions

- **OQ-1 ADR-0014 item 4 (blocking: this packet does not merge until the owner answers).**
  - **The conflict.** ADR-0014 item 4 says: "The `foundation` aggregator treats a skipped job as a failure". `foundation` now accepts skipped lab jobs on two light runs: a Markdown-only pull request, which is a merge gate under ADR-0014 item 1, and a push to `main` whose merged tree equals the merged head. It still fails on any skip the `scope` decision does not explain. The merge gate for every pull request that changes code is unchanged.
  - **Proposed amendment of item 4:** "No merge with a failing, cancelled or skipped required check. The `foundation` aggregator fails on any failed or cancelled job, and on any skipped job except the lab jobs that its `scope` job skips on a light run: a pull request whose changed files are all Markdown, or a push to `main` whose merged tree equals the merged pull request head (docs/development/ci.md)."
  - **Options**, each a change to the `scope` step only:
    - (a) **Recommended: accept both light paths** and approve the amendment above.
    - (b) **Accept only the push path.** `scope` always sets `full=true` on pull requests, so no merge gate ever skips a job. The push path still needs the amendment, because a light push run passes `foundation` with skipped jobs. Markdown-only pull requests cost a full run again, about 39 to 42 billed minutes.
    - (c) **Restore item 4 literally.** `scope` always sets `full=true`, on pull requests and on pushes. No amendment is needed. Every merge again costs a second full run (about 39 to 42 billed minutes), and only the job consolidation saves minutes.
  - The owner's answer goes into an ADR-0014 amendment (or an approval record), this packet and STATUS.md before merge.
