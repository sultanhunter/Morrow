## Design

### 1. Versioning (P01.T02a §1 rules)

Additions go into the candidate `schemas/v1.1/{core,capabilities}.schema.json` by a deliberate `release-baseline.json` edit. **One replacement:** `EventEnvelope` (@2), declared in `changes.json` as `{kind:"definition", name:"EventEnvelope", replaces:"core:EventEnvelope", reason, adr:"ADR-0016"}`, because the v1 `payloadRef` is an `ArtifactRef` and event payloads are not artifacts. `inspectSupersededUse` then rejects product use of `core:EventEnvelope` and `Core_EventEnvelope`. Every other definition is a new name at `schemaVersion` 1: closed objects, every property required, bounded strings and arrays, `anyOf[…,null]` for nullable fields, NUL-free text (`^[^\u0000]*$`).

### 2. Shared types (core-v1.1)

```ts
type StreamPosition = string /*^[A-Za-z0-9_-]{16,512}$; AEAD-sealed per viewer by the emitting service; never a decodable sequence number; never compared by clients*/;
type PageCursor = string /*^[A-Za-z0-9_-]{16,512}$; AEAD-sealed*/;   type PageRequest = {after: PageCursor|null; limit: int 1..50};
// Ref family, v1 ref shape {organizationId, workspaceId, storeId: Id|null, kind: const, id, revision, digest}: ConversationRef "conversation", MessageRef "message",
//   ProjectRef "project", AccessRequestRef "access_request", OperationRef "operation", KillSwitchRecordRef "kill_switch_record", EventPayloadRef "event_payload" (revision 1).
type TrustClass = "provider_fact"|"approved_business_fact"|"reviewed_lesson"|"work_record"|"hypothesis"|"synthetic"|"untrusted_external";
type CitedRef = ArtifactRef | EvidenceRef | ProposalRef | QuestionRef;   // the C2 typed ref union; the four `kind` consts are distinct, so it is discriminated
type RestrictedSource = {capabilityId: CapabilityId; resource: ResourceRef /*v1*/; accountId: Id|null; fields: FieldList(1..100)};   // one `view` requirement
```
- **A RestrictedSource is one view requirement.** It maps 1:1 to a policy `PermissionRequest {capabilityId, verb:"view", resource, accountId, fields}`, so `createHumanPolicyService` and the agent kernel evaluate it unchanged. Sources are deduplicated by `(capabilityId, resource, accountId)`, merging fields (a union over 100 fields gives `RESTRICTIONS_EXCEEDED`). ResourceRef appears only as the requirement's resource, never in the ref union.
- **Part → requirement mapping.** A trusted reader resolves each cited record at exactly the cited `revision` and `digest` (§3 references):

| Part or ref | View requirements added to `restrictedSources` |
| --- | --- |
| `artifact` (ArtifactRef, optional AnchorRef) | `workspace.artifact.read` over `{kind:"artifact", id, storeId, connectionId:null}`, fields from the artifact read row (`content` until P07.T01 publishes one), plus the artifact revision's own recorded sources. The anchor adds none; it must belong to the cited artifact revision. |
| `proposal` | `view` on the proposal's `capabilityId` over each distinct target resource, with that target's fields and account. A proposal whose targets would exceed the source cap cannot be cited; its approval item links it instead. |
| `question` | `view` on `workspace.question.request` over W, with the ADR-0010 question read fields. |
| each `evidence_summary` EvidenceRef | Its `contentRef` artifact as above, plus, when `sourceResource` is non-null, the Evidence@2 `readSource` requirement (B4). Until Evidence@2 exists, such evidence cannot be cited (`REFERENCE_NOT_FOUND`, fail closed). |
| model call (agent messages) | The call's recorded `RestrictedSource[]` (B4). |
| `text`, `mention` | None. Mention targets are not refs. |

- **Trust rank**, least trusted first: `untrusted_external` < `synthetic` < `hypothesis` < `work_record` < `reviewed_lesson` < `approved_business_fact` < `provider_fact` (`docs/contracts/collaboration-defaults.json`). Synthetic evidence never reaches a production-workspace message (B4), so its place matters only in labs. P01.T02b may refine the rank in its own ADR.
- **Cursors (C5).** The service seals `{kind, organizationId, workspaceId, principalId, filterDigest, position, issuedAt}`; P07.T03/P06.T02a choose AES-GCM and rotation. A decryption or tamper failure is the transport's; the library checks the decoded claims (`checkCursorClaims`). Another principal, workspace, list kind or filter, or age over 24 h, gives `CURSOR_INVALID` (400). Cursors carry no record IDs, so this is not an existence oracle.

### 3. Conversations and messages

```ts
type ConversationSubject = {kind:"project"; projectId: Id; ownerPrincipalId: null} | {kind:"task"; taskId: Id; ownerPrincipalId: null}
                         | {kind:"ask"; ownerPrincipalId: Id /*server-derived: the creating human (C5)*/};
type ConversationSelector = {kind:"project"; projectId: Id} | {kind:"task"; taskId: Id} | {kind:"ask"; conversationId: Id};
type Conversation = {schemaVersion:1; id; organizationId; workspaceId; storeId: Id|null; revision /*1: no v1.1 command revises a conversation*/; createdAt;
  updatedAt /*equals createdAt; posts never change it*/; subject: ConversationSubject; lastPosition: StreamPosition|null /*viewer-relative*/};
type MessageStatus = "streaming"|"completed"|"failed"|"cancelled";
type MentionTarget = {kind:"human"; principalId: Id} | {kind:"agent"; installationId: Id};
type MentionRequest = {kind:"notify"} | {kind:"task"; objective: string(1..2048)} | {kind:"delegate"; objective: string(1..2048)};
type MessagePart = {kind:"text"; text: string(1..16384)} | {kind:"artifact"; ref: ArtifactRef; anchorRef: AnchorRef|null}
  | {kind:"proposal"; ref: ProposalRef} | {kind:"question"; ref: QuestionRef}
  | {kind:"evidence_summary"; text: string(1..4096); evidenceRefs: EvidenceRef[1..50]; trustClass: TrustClass /*server-derived*/}
  | {kind:"mention"; target: MentionTarget; request: MentionRequest};            // allOf: human ⇒ notify|task; agent ⇒ delegate
type MessagePartInput = /* MessagePart without evidence_summary.trustClass */;    type MessageOrigin = {kind:"run"; runId: Id} | {kind:"ask_turn"; turnId: Id};
type Message = {schemaVersion:1; id; organizationId; workspaceId; storeId; revision; createdAt; updatedAt; conversationId: Id; position: StreamPosition /*viewer-relative*/;
  author: ActorRef /*human|agent; service is schema-invalid*/; status: MessageStatus; parts: MessagePart[0..32] /*mention parts: maxContains 10*/;
  replyToMessageId: Id|null /*viewer-relative*/; restrictedSources: RestrictedSource[0..100]; contextTaint: "none"|"untrusted_external"; origin: MessageOrigin|null};
// allOf: completed ⇒ parts ≥ 1; human ⇒ origin null ∧ status completed; agent ⇒ origin non-null ∧ no mention part.
type PostInput = {conversation: ConversationSelector; parts: MessagePartInput[1..32]; replyToMessageId: Id|null};
type MessageDelta = {schemaVersion:1; conversationId; messageId; sequence: Count; kind:"part_start"|"text_delta"|"part_end"|"message_end";
  partIndex: int 0..31; text: string(0..4096)|null; finalStatus: "completed"|"failed"|"cancelled"|null};
type StreamFrame = {kind:"event"; envelope: EventEnvelope} | {kind:"message_delta"; delta: MessageDelta} | {kind:"reset"} | {kind:"heartbeat"};
```
- **Subjects.** One conversation per project and per task, lazily ensured by the first post (idempotent). Ask conversations are created by `workspace.conversation.create`. They are private to `ownerPrincipalId` and to agents acting under that owner's Ask envelope; a workspace admin reads another member's Ask only through the audited admin read below (ADR-0016 item 5). No v1.1 command changes a conversation, so a post never changes its `revision` or `updatedAt`.
- **Authors and origin.** A human message is created `completed` in one command. An agent message is created `streaming` by the runtime writer with an origin: `run` in project and task conversations (the run's task is the subject task, or a task under the project's goal), `ask_turn` in an Ask. A lost lease on the run or turn moves it to `failed` (work_service), never `completed`.
- **Agent authority.** Agents read and post only through the kernel. In project and task conversations this is a task envelope (`decideDelegation`) or a mandate. In an Ask it is only the **Ask-bound envelope that P05.T04b adds** (Q3): `PrincipalWorkEnvelope` gains `subject: {kind:"task"; taskId; taskRevision} | {kind:"ask"; conversationId; conversationRevision}`; for an Ask, requester = authorizer = the Ask owner, `maximumDepth` 0, `maximumChildren` 0, capabilities limited to read capabilities and `workspace.conversation.post`. Until then there is no agent path into an Ask and the kernel denies it (fail closed). M2 needs no agent in an Ask; M5 (step 18) follows P05.T04b (step 16).
- **Visibility (C2), all-of.** A viewer sees a message only if all three hold under current grants: (a) subject view: project → goal view, task → task view, Ask → the viewer is the owner (an agent: the owner's Ask envelope) or a workspace admin through an audited admin read; (b) `view` on `workspace.conversation.post` for the message fields; (c) every `restrictedSource`. An invisible message is **omitted**: absent from pages and counts, `replyToMessageId` reads null, and `lastPosition` is the last visible position. Positions are sealed per viewer (P06.T02a/P07.T03 obligation) and posts never touch the conversation's revision or timestamps, so a hidden message leaves no gap, count, revision or timestamp signal.
- **Admin reads of Asks (ADR-0016 item 5).**
  - **Who.** A human member who currently holds `administer` on `workspace.conversation.create` with resource W and fields `storeId`, `subject`. This is the ADR-0010 item 1 ownership rule (another member's record → `administer` on its creating capability). No role title, template name, owner designation, other `administer` grant, governance capability or reviewer status qualifies. Agents never qualify: the capability is `human_only`, so an agent acting for an admin gets nothing.
  - **What.** Read-only and paged: the workspace's Ask list, the conversation record and message pages. Parts (b) and (c) of the visibility rule still apply, so a message citing a source the admin cannot view is omitted. No stream subscription, no Ask events, no inbox items, no post and no mention. The grant confers nothing else.
  - **Audit.** Each admin read (one list page, one conversation fetch or one message page) produces one content-free `AskAdminReadRecord {readerPrincipalId, conversationId, askOwnerPrincipalId, workspaceId, readKind: "list"|"conversation"|"messages", messageCount, correlationId, readAt}`. The consumer commits it in the same transaction as the read and returns content only after that commit; a failed or unknown commit returns no content. Records are append-only, carry no message text, keep the content-free audit retention (365 days) and are exported through `governance.audit.export`. An owner's read of their own Ask writes no record.
  - **Disclosure.** The `ask_conversation` route tells the Ask's creator that workspace admins can read Asks and that each admin read is audited.
  - **Oracle.** A member who is neither owner nor admin gets `REFERENCE_NOT_FOUND`, deep-equal to an unknown id. An admin may learn that an Ask exists; ADR-0016 accepts that disclosure.
- **Server-derived restrictions.** `restrictedSources` is the union of the part requirements and the context sources of every model call that produced the message (B4), deduplicated, at most 100 sources and 64 KiB of JSON. A human post over the cap gets `RESTRICTIONS_EXCEEDED`; the runtime splits agent messages. Sources only grow while `streaming`. `contextTaint` is `untrusted_external` if any cited evidence or context source is; `trustClass` is the least-trusted cited evidence class. Clients cannot send any of these (schema-invalid). For agent messages the runtime writer supplies them, and the library recomputes them: a mismatch is a writer assertion (`CollaborationBoundaryError("COLLABORATION_DERIVATION_MISMATCH")`), never a client-visible code.
- **Cost bound (published).** Each message has at most 102 view requirements: 100 sources plus subject and message view. A 50-message page evaluates each distinct requirement once per viewer against one authority snapshot: at most 5,100 pure in-Worker evaluations, and usually far fewer.
- **Streaming, in order.** For each model call: (1) its context sources are committed to the message; (2) every subscriber is rechecked against the grown set; (3) only then are that call's deltas sent, and only to subscribers who passed. Deltas that arrive earlier are held. A subscriber who fails gets the generic `reset` frame (also used for resubscription and policy-revision changes) and nothing more, and a refetch omits the message. Accepted disclosure: such a viewer may learn that a message started. Deltas are transient; a reconnect refetches the committed message and resumes at `sequence` > last seen.
- **References (C3).** Every cited ref, AnchorRef, tab artifact, scope resource and context ID must be in the trusted organization and workspace (and the conversation's store when set), exist at exactly the cited `revision` and `digest`, and be viewable by the actor now. `replyToMessageId` must name a message in the same conversation that the author can see. An Ask's `storeId` must be a store linked to W inside the creator's `view` scope on `workspace.conversation.post`. Every failure gives the same `REFERENCE_NOT_FOUND`.

### 4. Mentions (C3, C4): a scoped request, never authority

Checked in this order, so no rule is an oracle: (1) an agent-authored message with any mention part ⇒ `AGENT_MENTION_DENIED`, before any target lookup; (2) a mention in an Ask, a `delegate` outside a task conversation, or a duplicate target ⇒ `MENTION_NOT_ALLOWED`; (3) more than 10 mention parts ⇒ schema-invalid (`maxContains`); (4) each target must be an active member (human) or installation (agent) of the trusted organization and workspace **and** able to view the conversation subject now (humans: the human evaluator over the target's grants, as in ADR-0010 item 4; agents: the installation's and its owner's current grants). Unknown, foreign-tenant and no-access targets give the identical `REFERENCE_NOT_FOUND`; (5) at most 60 mention notifications per author per workspace per 10 minutes ⇒ `rate_limited` with `retryAfterSeconds`.

| Request | Target | Verb, held by the **author** and checked by `createHumanPolicyService` | Effect |
| --- | --- | --- | --- |
| `notify` | human | none beyond `execute` on `workspace.conversation.post` | one `mention` InboxItem for the target |
| `task` | human | `execute` on `workspace.task.create` | A draft task under the subject's goal (in a task conversation, `parentTaskId` = the subject task). Initiator and owner are the author; `allowedResources` defaults to `[W]`; the P06.T01a cap of 200 tasks per goal gives `limit_reached`. The target's item links it. Assignment stays a separate `workspace.task.assign`. |
| `delegate` | agent | `delegate` on `workspace.task.delegate`; only in a task conversation, with parent = the subject task | A delegated child task whose envelope is the author's authority ∩ the parent task scope ∩ the installation's grants. P05.T04b persists envelopes; until then P07.T03 rejects it as `MENTION_NOT_ALLOWED`. |

A mention never issues, widens or transfers a grant, never assigns, and never answers or approves; the target always acts under their own current grants. Only the subject-view eligibility check reads the target's authority; every authorizing request is the author's. A target who can view the subject but not some source of the message receives an item that re-filtering keeps hidden until they can (§5), and the author learns nothing beyond subject eligibility. All mention effects commit atomically with the message, or nothing commits.

### 5. Inbox projection (C1)

```ts
type InboxKind = "question"|"approval"|"access_request"|"exception"|"assignment"|"mention"|"stop_notice"|"stop_proposal";
type InboxSubject =   // discriminated by kind; must equal InboxItem.kind
  | {kind:"question"; questionRef: QuestionRef} | {kind:"approval"; approvalRef: ApprovalRef; proposalRef: ProposalRef}
  | {kind:"access_request"; accessRequestRef: AccessRequestRef} | {kind:"assignment"; taskId: Id; assignmentId: Id}
  | {kind:"exception"; reason:"uncertain_operation"|"failed_operation"; operationRef: OperationRef}
  | {kind:"exception"; reason:"quorum_unreachable"; proposalRef: ProposalRef; approvalRef: ApprovalRef}
  | {kind:"mention"; messageRef: MessageRef; conversationId: Id|null; request: "notify"|"task"|"delegate"; createdTaskId: Id|null}   // both IDs viewer-relative
  | {kind:"stop_notice"; killSwitchRecordRef: KillSwitchRecordRef} | {kind:"stop_proposal"; proposalRef: ProposalRef};
type StopProposalStatus = "open"|"executed"|"dismissed"|"expired";   // derived, not stored
type DecisionState = {machine:"question"; status: QuestionStatus} | {machine:"approval"; status: ApprovalStatus} | {machine:"access_request"; status: AccessRequestStatus}
  | {machine:"operation"; status: OperationStatus} | {machine:"task"; status: TaskStatus} | {machine:"stop_proposal"; status: StopProposalStatus} | {machine:"none"; status:"informational"};
type InboxItem = {schemaVersion:1; id; organizationId; workspaceId; storeId; revision; createdAt; updatedAt; recipientPrincipalId: Id /*= viewer*/; kind: InboxKind;
  subject: InboxSubject; decisionState: DecisionState; open: boolean; readState: "read"|"unread"; readAt: UtcTime|null;
  context: {projectId: Id|null; taskId: Id|null} /*viewer-relative: null unless viewable*/; position: StreamPosition /*sealed per recipient*/};
type InboxFilter = {kinds: InboxKind[0..8] /*unique; [] = all*/; readState: "read"|"unread"|null; open: boolean|null; projectId: Id|null};
type InboxMarkInput = {itemIds: Id[1..100] /*unique*/; state: "read"|"unread"};   type InboxPage = {items: InboxItem[0..50]; next: PageCursor|null};
```
- **Kind → machine** is fixed: question → question; approval → approval; access_request → access_request; exception → operation, or approval for `quorum_unreachable`; assignment → task; stop_proposal → stop_proposal; mention and stop_notice → none. A mismatched machine is schema-invalid.
- **`open`** comes from a fixed table in `collaboration-defaults.json`: question `open`; approval `pending`; access_request `pending`; operation `uncertain`, `conflict`; task `draft`, `ready`, `waiting_input`, `waiting_approval`, `paused`; stop_proposal `open`; none never. The Inbox badge counts open items. A `failed_operation` exception is intentionally never open: the operation is terminal and needs no decision, so it arrives unread and is not counted.
- **Read state is separate (C1)** and per recipient. Marking read or unread never changes `decisionState`, and deciding never changes `readState` ("unread is not unapproved").
- **Recipients.** question: the respondent; approval: eligible non-conflicted reviewers (ADR-0011); access_request: the deciders of §6, never the requester; exception: the task owner and initiator (quorum: the proposal's `requestedBy`); assignment: the new owner unless they are the actor; mention: the target; stop_notice: the designated owner (ADR-0009 owner record), always; stop_proposal: humans holding `execute` on that kill switch covering every target. One item per (recipient, kind, subject id); duplicate events create one logical item (P07.A03).
- **Re-filtered at read time (C2).** An item is returned only if the viewer is its recipient, holds `view` on `workspace.inbox.read`, and can view the subject now: the question read, approval preview eligibility, the access request (§6), the operation's task, the task, the KillSwitchRecord targets, and for mentions the whole message under §3 including its sources. Otherwise it is omitted. `context`, the mention `conversationId` and `createdTaskId` are null unless viewable. **Exception:** a `stop_notice` to the designated owner is never target-filtered, because it is the ADR-0005 owner notification; it shows the KillSwitchRecord fields only (capability, target keys, actor, reason).
- **Stop proposals.** A `stop_proposal` is a kill-switch Proposal with no Approval. Its status is **derived**, with precedence executed > dismissed > expired > open: `executed` when a KillSwitchRecord cites it as `sourceProposalRef`, `dismissed` when a dismissal exists, `expired` at `expiresAt`. A dismissal (`StopProposalDismissInput {proposalRef, reason: string(1..1024)}`, persisted by P11.T05) needs `execute` on the proposal's kill-switch capability covering every target, checked through `checkKillSwitchTarget`. An unknown, hidden or uncovered proposal gives that function's `TARGET_NOT_FOUND`; a proposal that is not open gives `STOP_PROPOSAL_NOT_OPEN`.

### 6. Projects and access requests

```ts
type ProjectTab = {id: Id; title: string(1..60); artifactId: Id};   type ProjectTabInput = {title; artifactId};
type Project = {schemaVersion:1; id; organizationId; workspaceId; storeId: null; revision; createdAt; updatedAt; goalId: Id /*one project per goal*/;
  title: string(1..120); pinned: boolean; pinRank: int 0..19 | null /*viewer-relative dense rank; null ⇔ unpinned*/; tabs: ProjectTab[0..20] /*viewer-relative; order = tab order*/};
type AccessRequestStatus = "pending"|"granted"|"denied"|"withdrawn"|"expired";
type AccessRequestScope = {capabilityId: CapabilityId; verbs: GrantVerb[1..6] /*unique*/; storeIds: IdList(0..10); accountIds: IdList(0..10);
  resources: ResourceRef[0..100]; fields: FieldList(1..100)};
type AccessRequest = {schemaVersion:1; id; organizationId; workspaceId; storeId: null; revision; createdAt; updatedAt; requester: HumanActorRef; scope: AccessRequestScope;
  reason: string(1..1024); context: {projectId: Id|null; taskId: Id|null; conversationId: Id|null} /*viewer-relative*/; status: AccessRequestStatus;
  proposalRef: ProposalRef|null; decidedBy: HumanActorRef|null; expiresAt: UtcTime};
type AccessRequestDecisionInput = {accessRequestId: Id; expectedRevision; reason: string(1..1024)};   type AccessRequestWithdrawInput = {accessRequestId: Id; expectedRevision};
```
- **A project is a pinned Goal**: a UX record over one goal, not a tenant or permission boundary. Reading it, and viewing a project conversation's subject, is **goal view** (Q2): `view` on `workspace.goal.create`, whose vocabulary gains the project fields. Agents can therefore read the projects they work in. Tabs reference artifacts by id and show the current revision; unviewable tabs are omitted. Each tab `artifactId` must pass the §3 reference rule for the writer. One project per goal (`PROJECT_EXISTS`; the creator already holds goal view, so this is no oracle).
- **Pins** are workspace-wide: one shared order and at most 20. Each viewer sees only the pinned projects they can view, ranked densely from 0. `beforeProjectId` must be a pinned project the actor can see, otherwise `REFERENCE_NOT_FOUND`. Accepted disclosure: `limit_reached` at 20 tells a pinner that the workspace holds 20 pins, a count with no IDs.
- **Access requests are human-only (C5).** Agents have no authority-request path in v1.1; they can only ask a human through `workspace.question.request` on their task. A request never grants anything.
- **Deciders.** A decider is an eligible reviewer of the would-be `governance.grants.revise` proposal, by the ADR-0011 Q5 rule: `approve` on `governance.approval.decide`, plus `approve` on `governance.grants.revise` covering every requested resource (W when none), store and account. The requester is conflicted (ADR-0011 Q1) and never decides. **Deny** is a decider with `AccessRequestDecisionInput`. **Withdraw** is the requester's `execute` on `governance.access.request` (ADR-0010 ownership rule; `administer` never withdraws for someone else). Neither needs a new capability (Q2).
- **Linkage (P05.T02b).** P05.T02b extends P05.T02a's grant-revision proposal command with `originAccessRequestId: Id|null`, which links the request in the same transaction; the proposer is the human creating that proposal. The request must be pending and unlinked (`ACCESS_REQUEST_NOT_PENDING`). The proposal must be in the same tenant, its capability must be `governance.grants.revise`, the proposed grant must be for `scope.capabilityId`, and its beneficiaries must include the requester; otherwise `REFERENCE_NOT_FOUND`. When the linked proposal's grant revision commits, the request becomes `granted`. That revision may be narrower than requested under a partial approval; `proposalRef` then names the approved derived proposal, so the requester reads exactly what was granted. A rejection sets `denied` (with `decidedBy` the rejecting reviewer). Expiry or invalidation of the proposal clears the link.
- **Limits.** A pending request expires after 7 days, and each requester may hold at most 20. The scope's `capabilityId` must exist and not be `operator_*`. Every scope resource and context ID must pass the §3 reference rule for the requester. Reads: the requester (`view` on `governance.access.request`) and the deciders.

### 9. Transitions, errors, idempotency and binding notes

- **Transitions** (`state-transitions.json`, rows `since:"1.1"`). `message`: `streaming→completed`, `streaming→failed`, `streaming→cancelled` (runtime, `current_lease`, of the run or Ask turn); `streaming→failed` (work_service, `lease_lost`); human messages are inserted `completed`. `access_request`: `pending→granted` (work_service, `linked_grant_revision_committed`); `pending→denied` (eligible_decider, `decider_rule_not_requester`); `pending→denied` (work_service, `linked_proposal_rejected`); `pending→withdrawn` (requester); `pending→expired` (work_service, `expires_at_passed`). Stop-proposal status is derived (§5); projects and conversations have no status machine.
- **Commands** use the CommandEnvelope with per-actor `(commandId, requestDigest)` idempotency (ADR-0010). The same key with another digest gives `conflict`/`never`. `uncertain` is returned only after submission, and a same-key retry reconciles. Mark and dismissal are idempotent target states without `expectedRevision`; revise, pin, deny and withdraw take it.
- **Errors** (v1 ErrorEnvelope, fixed safe messages). `REFERENCE_NOT_FOUND` → 404 `denied`/`never`, byte-identical except `correlationId`; dismissal uses `TARGET_NOT_FOUND` with the existing kill-switch envelope. `AGENT_MENTION_DENIED`, `PERMISSION_DENIED` → 403 `denied`/`never`. `MENTION_NOT_ALLOWED`, `CURSOR_INVALID` → 400 `missing_input`/`never`. `PROJECT_EXISTS`, `LIMIT_REACHED`, `RESTRICTIONS_EXCEEDED` → 409 `conflict`/`never`. Stale revisions, `ACCESS_REQUEST_NOT_PENDING`, `STOP_PROPOSAL_NOT_OPEN` → 409 `conflict`/`recheck_before_retry`. `RATE_LIMITED` → 429 `rate_limited` with `retryAfterSeconds`. Writer assertions are internal failures and are never echoed.
- **Binding on P01.T02b (B4).** ModelCall `subject: {kind:"task"; taskId; runId} | {kind:"ask"; conversationId; turnId}`, which settles task-less Asks (C5); each call records its context as `RestrictedSource[]`; Evidence@2 `$ref`s `TrustClass` and records a `readSource` requirement; synthetic evidence never reaches a production-workspace message; model deltas map into `MessageDelta`.
- **Binding on P05.T04b.** The Ask-bound envelope of §3. **On P05.T02b.** Access-request persistence, commands, expiry, `originAccessRequestId` linkage and its events. **On P06.T02a.** The envelope mapping, registry validation, payload nulling, event re-filtering, sealed positions and cursors, and `StreamFrame` transport. **On P07.T03.** Persistence and enforcement of §3–§5 and the project parts of §6, the stream gate order, the mention rate, and tenant-conformance registration including recipient-only inbox RLS and owner-only Ask RLS. Admin reads of Asks go through a definer that rechecks the ADR-0016 grant and inserts the `AskAdminReadRecord` in the read's transaction, never through a widened RLS policy. **On P05.T01z, P11.T05, P06.T01b and P06.T01c.** Emit their registry rows; P11.T05 persists dismissals.

## Security review checklist

- [ ] No conversation, message, mention, inbox, project, access-request or event shape or library path issues, widens, transfers or revives a grant (AC12, AC16). A mention is a request under the author's own verbs; only subject eligibility reads the target's authority.
- [ ] Agent-authored mentions are rejected before any target lookup. Agents get no verb on the six `human_only` capabilities, have no access-request path, and reach Asks only through the P05.T04b Ask envelope.
- [ ] Every ref is bound to its stored record (tenant, `revision`, `digest`) and current view; replies, anchors, context IDs and the Ask store are checked; failures fold to one deep-equal denial and a byte-identical 404.
- [ ] Message visibility is all-of over subject, message view and sources; restrictions are server-derived, bounded and only grow; omission leaves no count, position, revision, timestamp or reply-pointer signal.
- [ ] Streaming commits a call's sources and rechecks subscribers before any of its deltas leave.
- [ ] Inbox items are re-filtered at read time, contexts are viewer-relative, and the owner's `stop_notice` is never suppressed. Read state never alters decision state.
- [ ] Asks are owner-only except audited, read-only admin reads under `administer` on `workspace.conversation.create` (ADR-0016 item 5). No other grant, title or ownership record qualifies; admins get no events, stream or post; every admin read plan requires an audit record, and agents never take the admin path.
- [ ] Event payloads are IDs and statuses only; nulled payloads also null the ref; positions and cursors are sealed and never decodable.
- [ ] Access-request deciders follow the ADR-0011 reviewer rule and exclude the requester; linkage needs the requester among the beneficiaries.
- [ ] Limits and disclosures (stream start, pin count) are published; text is NUL-free; schemas are closed and bounded; validators are AOT only; the replaced v1 envelope is unusable in product code.
- [ ] The AI review is labelled "separate context, same model family".
