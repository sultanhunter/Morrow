## Goal (observable product delta)

**Dry-run.** `npm run edge:dry-run` builds deployable bundles for the four selected Workers in all three environments, with no Cloudflare account, credentials or network.

**Local dev.** `npm run dev:edge` serves the workspace SPA and the native workspace API on one loopback HTTPS origin, `https://127.0.0.1:8787`, in **unbound mode only**. Unbound is the only local mode that needs no approval. Configured mode would bind real `*.neon.tech` and `api.workos.com`, which is a Tier 3 live effect. Configured journeys therefore run only in the labs.

**The four Workers:**
- **api** (`morrow-<env>-api`): Static Assets serve `apps/workspace-web/dist` on the same origin as `/auth/*`, `/workspace/*`, `/api/*` and `/healthz`, which the `__Host-` cookies require. Bindings map to `ManagedWorkspaceApiDependencies` once per isolate; any problem falls back to the existing deny-all instance. It keeps the keyless WorkOS PKCE exchange and the JWKS read (plan R1, P04.T02a bullet), and it holds no provider credential.
- **broker** (`morrow-<env>-broker`): no public route; reachable only through the `ApiBroker` service-binding entrypoint. It holds the WorkOS key and the 7 Neon runtime-role passwords. It makes the keyed WorkOS session-catalogue read and leases role passwords to the api, which closes the P05.T01v deviation (invariant 11). It is **not** a general credential broker (D3).
- **orchestrator** (`apps/workers`): a Workflow class plus a Queue consumer, with dispatch hard-disabled.
- **connector** (existing `apps/shopify-connector`): a 503 placeholder.

**Lab.** A workerd lab runs login → callback → bootstrap → link status → logout through the real api and broker bundles, against synthetic WorkOS and real PostgreSQL 17. The api never sees the WorkOS key; its only WorkOS requests are the keyless POST and the JWKS GET.

## Design

### D1 Topology and trust

```
browser ─https─▶ api (Static Assets + reserved paths) ─service binding, ApiBroker RPC─▶ broker ─▶ api.workos.com (sessions GET, keyed)
                 api ─▶ api.workos.com (keyless authenticate POST, JWKS GET);  api ─▶ wss://<ep-host>/v2 (Neon, leased passwords)
```

- The orchestrator and connector have no service bindings.
- Every Worker sets `workers_dev:false` and `preview_urls:false`, and has no `routes`. P04.T01i adds a domain to the api only.
- The service-binding boundary is the Cloudflare account plus its deploy permissions; ADR-0007 records this. Deployment identities stay in P04.T02.

### D2 Credential custody (ADR-0007)

| Credential | Bound to | Reaches the api? |
| --- | --- | --- |
| WorkOS API key | broker secret `WORKOS_API_KEY` | Never; the broker makes the one keyed call |
| 7 Neon runtime-role passwords | broker secrets `MORROW_DB_PASSWORD_<ROLE>` | Yes, per pool connect, through `neonLease` |
| Login capsule keyring | api secret `LOGIN_CAPSULE_KEYRING` | It is the api's own application key (invariant 11) |
| Owner, migration, lifecycle and maintenance passwords; Neon API key; Cloudflare tokens | no Worker | Never |

**The lease carries a static password.** `neonLease` returns the role's **static password**, which has no credential lifetime. `expiresAtMs` only bounds the pool's use within one request. The same password serves the primary and the observer, and the frozen lease keeps it for the life of the request-scoped pool. "Short-lived broker leases" (invariant 11) therefore describes the lease object, not the secret.

**What a password allows that a fixed-statement proxy would not:** catalog reads (including `pg_proc` source); TEMP objects, since PUBLIC TEMP is never revoked in `infra/*.sql`; overriding `statement_timeout` and other USERSET settings; exhausting CPU or connections; and connecting from anywhere, because Neon endpoints are public.

**R1: session-issuer forgery.**
- `resolve_provider_subject_selection` (0007:112-116, `morrow_identity_resolution`) returns exactly the profile, mapping, binding, membership and policy identifiers that `admit_browser_family` (0008:194-245, `morrow_identity_sessions`) needs.
- Admit accepts a subject, provider session, evidence times and digests, and secret digest all chosen by the caller. It needs no earlier exchange or login-flow row, and it checks nothing with WorkOS.
- So anyone holding those two passwords, a `user_` id and a workspace id can mint a valid `__Host-morrow_session` in any tenant of that environment.
- **A one-time leak from api memory gives persistent cross-tenant session forgery until the issuer passwords rotate.**

**R2: session-metadata read.** Through `workosSessionPage`, a compromised api can read session metadata (IP address, user agent, timestamps) for any `user_` id in the WorkOS environment.

**Why lease anyway, for development and staging only:**
- invariant 11 prescribes leases;
- a proxy would move `new Client`, the socket guard, observer verification and request-owned cleanup (bound to the api's `ctx.waitUntil`) into another isolate, rewriting pool code frozen by ADR-0003 (size L);
- only synthetic data exists before P09.T05;
- production stays unbindable (D6 step 7).

**Resolved 2026-10-17 (OQ2, option A):** ADR-0007 accepts R1 and R2 for development and staging only. The long-term option is the production credential custody decision, which is still pending and needs a superseding ADR before any production binding or deploy.

**Compensating controls.** ADR-0007 lists them; P04.T01i applies them as hosted operations (not migrations) and sizes them:

```sql
ALTER ROLE morrow_api CONNECTION LIMIT :n;                          -- each of the 7 runtime roles
ALTER ROLE morrow_api SET statement_timeout = :profile_ms;          -- defaults only: the holder can SET them back,
ALTER ROLE morrow_api SET idle_in_transaction_session_timeout = :ms; -- so they bound accidents, not an attacker
REVOKE TEMP ON DATABASE morrow FROM PUBLIC;                         -- no migration uses TEMP (AC19 proves it)
```

- Rotate every 90 days, and immediately on suspected exposure. AC20 is the local precursor to P04.A02.
- Monitor connections by role and `application_name`. P04.T03a alerts on unknown names.
- No network allowlist: the plan never offers one, and Workers egress from shared Cloudflare ranges.

### D3 Broker trust model and RPC rules

- **Trust.** v0 trusts every caller that holds the binding. It performs none of P04.T02's "fresh policy, scope, operation and budget checks", which is acceptable only for these pre-authentication identity calls and role leases. ADR-0007 states that Shopify, OpenAI, E2B and any other merchant or model credential **must not** be added under this model; they wait for the P08.T02 broker.
- **Values.** Only strings, booleans and integer budgets cross the boundary: no AbortSignal, absolute time or object result. Callers decode strictly, and returning primitives avoids any disposer RPC may attach to objects (M4).
- **Budgets.** The api sends `budgetMs = min(max, control.deadlineMs − now())`; a value ≤ 0 means no RPC is made. The api races each call against its own timer and `control.signal`, discards late results, and never retries. The broker builds `{deadlineMs: Date.now()+budgetMs, signal}` only for calls that do I/O. `neonLease` takes no budget.
- **Errors.** Every failure rejects with `Error("BROKER_HELD")` and writes one log line `{"event":"morrow_broker","method","code"}`. The code is one of INPUT_INVALID, NAMESPACE_DENIED, CAPABILITY_UNAVAILABLE, BUDGET_INVALID or PROVIDER_HELD. No value, URL, namespace field or secret is ever logged or returned.

### D5 Broker Worker (`apps/broker`, `@morrow/broker`)

- **Entrypoint.** `src/index.ts` declares `ApiBroker extends WorkerEntrypoint<unknown> implements ApiBrokerRpc` with exactly three prototype methods. Each method checks `arguments.length` and forwards to a module-scope handler. The default export is `{ fetch: () => 404 {"code":"not_found"} }`.
- **Initialisation.** `src/capabilities.ts` exports `brokerCapabilities(env)`. It is memoised per isolate in a `WeakMap<object, Promise>` with **one in-flight initialisation**, which concurrent first calls share. It reads fixed names as own data properties, never rejects, and awaits `parseLoginConfiguration` and `createWorkersFixedWorkosLoginPort`. A failed initialisation resolves to "nothing ready" and stays held for the life of the isolate.
- **Readiness.** `sessions` is ready when the configuration parses, its `retentionTier` equals `MORROW_ENVIRONMENT`, the port initialises, and `WORKOS_API_KEY` matches `^sk_test_[\x21-\x7e]{8,4088}$` (development or staging) or `^sk_live_…$` (production). `database` is ready when the binding parses for `MORROW_ENVIRONMENT` and all seven passwords pass the pool rules (16–1024 UTF-16 units, no control characters or spaces, well-formed).
- **`neonLease(ns)`.** Requires `database`, plus an `ns` of at most 1024 bytes that is byte-equal (no parsing) to exactly one `neonLeaseNamespace(binding, role)`. It returns `encodeNeonLeaseGrant(env[brokerPasswordSecret(role)])`, with no state, side effect, budget or retry.
- **`workosSessionPage(ns, selector, budget)`.** Requires `sessions`, `ns === workosSessionNamespace(config)`, a selector of at most 2048 bytes, and an integer budget from 1 to 10000. It makes exactly one `port.readSessionPage(selector, {deadlineMs: Date.now()+budget, signal})`, whose result must be a string of at most 131072 bytes. The port's broker-local `borrow(n, c)` requires that namespace and returns `{namespaceJson:n, credential: WORKOS_API_KEY, expiresAtMs: c.deadlineMs, revocationSignal: new AbortController().signal, release: async () => {}}`. `exchange` and `readPublicKeyset` are never exposed.
- **`health()`** returns `sessions && database`.

### D6 api composition (`apps/api`)

**`src/environment.ts`.** `mapApiEnvironment(env: unknown, now = () => Date.now())` is synchronous and never throws. It returns `{ok:true, environment, values}` or `{ok:false, code}`, and the first failing check decides the code:

1. `env` is a non-null object, else `API_ENV_RECORD_INVALID`.
2. `globalThis.process?.env` has no keys, else `API_ENV_PROCESS_ENV_POPULATED`.
3. No own key matches `/^(WORKOS_|MORROW_DB_PASSWORD_|SHOPIFY_|OPENAI_|E2B_|NEON_|PG)/i`, and none other than `LOGIN_CAPSULE_KEYRING` contains `KEY|SECRET|PASSWORD|TOKEN`, else `API_ENV_FORBIDDEN_CREDENTIAL_BINDING`.
4. `MORROW_ENVIRONMENT` is one of the three environments, else `API_ENV_ENVIRONMENT_INVALID`.
5. Of `LOGIN_CONFIGURATION_JSON`, `WORKSPACE_CONFIGURATION_JSON`, `LOGOUT_CONFIGURATION_JSON`, `MORROW_DATABASE_BINDING_JSON` and `LOGIN_CAPSULE_KEYRING`: none present gives `API_ENV_UNBOUND` (every committed environment); some present gives `API_ENV_PARTIAL`.
6. Each value is a well-formed string within its limit of **32768 / 2048 / 8192 / 4096 / 4096** bytes, matching the identity limits; object values fail. Else `API_ENV_VALUE_INVALID`.
7. `captureManagedWorkspaceBinding` passes, and both the database environment and the login `retentionTier` equal `MORROW_ENVIRONMENT`, else `API_ENV_CROSS_BINDING_MISMATCH`. Production always fails this check.
8. The keyring is JSON with purpose `morrow.login.capsule/1` (the digest check stays request-budgeted), else `API_ENV_VALUE_INVALID`.
9. `env.BROKER` is an object with a function `fetch`, else `API_ENV_BROKER_BINDING_INVALID`.

The mapper uses only the synchronous `captureManagedWorkspaceBinding` and `loginJson`; `workosSessionNamespace` derives the WorkOS namespace from their output.

**`composeApiDependencies(values, broker, now)`** is the single place dependencies are assembled, and the extension point for T01x.
- `credentialBroker = createBrokerNeonCredentialBroker(broker, now)`.
- `providerPort` is `{exchange, readPublicKeyset}` from `createLazyWorkosLoginPort(values.login, now)` plus `readSessionPage: createBrokerSessionPageReader(broker, workosSessionNamespace(values.login), now)`.

**`src/workos-port.ts`.** Per isolate, it memoises one in-flight `createWorkersFixedWorkosLoginPort({configurationJson, sessionCredentialBroker: deny, now})`.
- `deny.borrow` always rejects, so this local port can never obtain a key.
- Each method races the memoised port against `control`. A failed initialisation stays held.
- `readiness()` gets the digest from `parseLoginConfiguration`, runs `parseManagedLoginKeyring(keyring, digest)`, and reads the current window.

**`src/broker-client.ts`** (DOM-typed, structural, with no `cloudflare:` import):

```ts
export function createBrokerNeonCredentialBroker(broker: ApiBrokerRpc, now: () => number):
  Readonly<{ borrow(namespaceJson: string, control: Readonly<LoginControl>): Promise<unknown> }>;
export function createBrokerSessionPageReader(broker: ApiBrokerRpc, workosNamespaceJson: string,
  now: () => number): WorkosSessionPageReader;
export function createBrokerHealth(broker: ApiBrokerRpc, now: () => number): () => Promise<boolean>;
```

- **`borrow`.** It validates the control's own data. An aborted control, or `deadlineMs − now() ≤ 0`, rejects with no RPC. Otherwise it makes one `neonLease`, raced against the signal and a timer, and decodes the result. It returns `Object.freeze({namespaceJson, password, expiresAtMs: control.deadlineMs, revocationSignal: new AbortController().signal, release})`. This `expiresAtMs` adds nothing beyond the pool's own D (:658). `release(c)` validates, resolves locally and is idempotent. It never aborts the signal, because the pool's `wait(releaseLease)` listens on it, and it makes no RPC.
- **Reader.** Budget `min(10000, deadline − now())` and one RPC. Anything other than a string of at most 131072 bytes is held.
- **Health.** A 1000 ms timeout, cached for 30 s per isolate with a single in-flight call, so a public `/healthz` cannot amplify broker calls.

**`src/deployed-worker.ts`** (the wrangler `main`).
- **Per-`env` instance.** A WeakMap keyed by the `env` object holds either `createWorkspaceApiWorker(composeApiDependencies(…))` or, on failure, the unbound `createWorkspaceApiWorker()`. A failure logs one fixed line `{"event":"morrow_api_unbound","code"}`.
- **`/healthz`.** GET and HEAD return 200 `{"schemaVersion":1,"service":"api","ready":bool}` with no-store and nosniff; other methods get 405. `ready` = configured ∧ port ready ∧ keyring window contains now ∧ cached broker health. Once per isolate it logs `{"event":"morrow_api_keyring","code"}` with `KEYRING_EXPIRING` (fewer than 14 days left), `KEYRING_NOT_YET_VALID` or `KEYRING_EXPIRED`.
- **Everything else** goes to `selected.api.fetch(request, env, ctx)` with the real ctx and no await before it. The response is returned unchanged, with no header added or removed.

- `verify-config` requires `run_worker_first` to equal this list in every environment, and fails if any `workspace-routes.json` pattern falls under a reserved prefix. `workspace-routes.md` gains one sentence about this.

### D7 Login keyring lifecycle and tool

- **Window (decision K1 in ADR-0007).** A single version, with `encryptFromMs = t0 − 300000` (clock skew), `encryptUntilMs = t0 + 90 d` and `decryptUntilMs = encryptUntilMs + 300000` (the parser maximum).
- **Rotation.** Every 60 days, on any login-configuration change (the keyring is bound to the digest), and on suspected exposure.
- **Overlap.** Cloudflare secrets are write-only, so a two-version keyring would mean keeping old material outside Cloudflare. K1 instead accepts that logins in flight during a rotation fail with the existing "Sign-in could not be completed" page and restart. That is at most 300 s of logins, plus isolates still on the old version. K2 is not adopted (OQ1, resolved 2026-10-17 in ADR-0007).
- **Atomic deploy.** Vars and keyring ship as one version: `wrangler deploy --env <e> --secrets-file <file>`. A bare `secret put` would create a version whose digest mismatches its vars.
- **Outside the window.** Past `encryptUntilMs`, or before `encryptFromMs`, login start returns 503 `{"schemaVersion":1,"outcome":"login_unavailable"}` and `/healthz` is not ready.
- **Tool.** `scripts/login-keyring.mjs --config <login-config.json> --out <absolute path>`: it refuses an `--out` inside the repo or `MORROW_ARTIFACTS_DIR`, an existing path, or a symlinked parent; it creates the file exclusively (`wx`, no-follow) with mode 0600, containing `{"LOGIN_CAPSULE_KEYRING":"…"}`; it prints only `{keyId, encryptFromMs, encryptUntilMs, decryptUntilMs, configurationDigest}`. Agent shells are pipes, so material must never reach stdout or stderr. The owner runs it for hosted environments. Agents run it only on synthetic configurations, writing into scratch directories.

### D9 wrangler configuration and local dev

- **Four `wrangler.jsonc` files.** Per-environment keys (`vars`, `services`, `secrets`, `queues`, `workflows`) are repeated in every environment.

### D10 Idempotency, concurrency, unknown outcomes

- **Broker.** Stateless. All three methods are idempotent, concurrency-safe reads, and concurrent first calls share one initialisation.

- **Configuration.** Captured once per isolate; it changes only with a new Worker version.
- **Queue.** Messages are never consumed, so they end up in the DLQ.

## Security review checklist

- [ ] Only the broker binds provider credentials (AC04, AC07). The api's only secret is its own keyring (invariant 11).
- [ ] The WorkOS key never leaves the broker (AC13). The api's WorkOS calls are keyless, and its local credential broker always rejects.
- [ ] Neon passwords leave the broker only via `neonLease`: only on `ApiBroker`; only for the 7 pairs of the broker's own binding; never logged; never for the owner, lifecycle, maintenance or migration roles.

- [ ] The v0 trust model is documented, and no merchant or model credential is added under it.
- [ ] RPC surface: exactly 3 methods, with helpers at module scope; `arguments.length`, types, byte limits and integer budgets are validated; results are primitives; every failure is the single error `BROKER_HELD`.
- [ ] No Worker has a route, `workers.dev` or preview URLs. The broker's default `fetch` returns 404.
- [ ] `nodejs_compat_do_not_populate_process_env` is set on every Worker, with a negative control (AC08).
