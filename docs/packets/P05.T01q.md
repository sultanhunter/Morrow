## Scope and authority

P84 issues an independent15-minute Morrow family and proves cookie consumption by O/B, but expressly excludes end-user logout. Its owner-only revocation functions are synthetic maintenance facilities. This increment supplies a distinct current-family-only self-service boundary. It does not supply provider logout, all-device logout, refresh, generation rotation, SSO/SCIM, provisioning, real Shopify or accepted feature UI.

Possession of the exact current Request's opaque session cookie may retire only the immutable new-family/generation relationship selected by its server-derived SHA256. This is a narrowly defined credential-retirement permission, independent of selected-workspace domain authorization. Suspended/revoked workspace membership, inactive principal/mapping/profile/provider binding, expired family/generation or revoked generation must not trap the holder in a family they cannot retire. None of these facts authorizes reading a workspace, issuing a grant, targeting another family or revoking an upstream provider session.

Namespace comes from trusted configuration and immutable SQL profile/provider facts. Body/query/header values cannot select a principal, organization, workspace, provider session, family or generation. Only an unambiguous match in the Morrow browser-family representation is supported; a matching legacy sessions row, an absent generation, a foreign namespace or an inconsistent family/generation relationship denies. An already ended matching family is an idempotent terminal no-op.

## One request and no cookie deletion

Use one POST /auth/logout. Mandatory HMAC prepare/apply was considered and is unnecessary for this packet: the owned client/controller performs no automatic retry, each Request captures its Cookie once, and no latent client family selector survives into another Request. Exact-request replay uses the same captured proof. A later deliberate action with a newly current cookie is legitimately a request to end that new family. Do not claim semantics for an external caller that constructs a new Request with a different cookie and calls it a replay of a prior body.

Logout never sends Set-Cookie, expires a fixed-name cookie, clears __Host-morrow_login or changes another response. A delayed deletion of __Host-morrow_session could erase a newer login cookie because HTTP cookies offer no conditional delete-by-old-value operation. Server revocation supplies the security effect; the old opaque cookie remains inert until its normal expiry or explicit later login replacement. This deliberately avoids that deletion race without inventing a second key, ticket or durable intent ledger.

The acknowledgement concerns only the captured credential's family. It is not proof that the browser has no other newly installed credential, that another pending login is cancelled, or that no future login may complete. P84's independent explicit login may create another family; this packet does not add a global logout fence or latest-login-wins behavior.

## Cancellation and unknown effects

Before the end-function is invoked, parse/CSRF/cookie/config failures have no revocation effect. Latch function invocation before calling the trusted client. Any query/COMMIT/disposal rejection, timeout, abort, malformed result or late callback at/after that latch yields conservative outcome_unknown. Close/latch the facade before propagating uncertain query failure; no automatic ROLLBACK or subsequent SQL through it. A known completed denial can use the existing bounded rollback pattern. Dispose every late connection and await actual release before any success; all attempt/completion/backend facts remain separate.

No automatic HTTP, SQL or UI retry exists. An explicit later user request is a new capture of the then-current cookie; already ended immutable state is safe to acknowledge, and this does not replay an unknown mutation or manufacture a replacement command inside an earlier attempt. No public status/reconcile endpoint or generic administrative revocation endpoint is added. A returned200 follows acknowledged commit and disposal, but is not proof of browser delivery. Same-stack sink ownership is retained; sink throws, returned thenables or disconnects cannot produce a second response or cookie operation.
