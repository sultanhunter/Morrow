## Shared application and SQL contract

The expected fields are conflict selectors from77, never authority. Provider/subject/session/profile proof values come only from a freshly owning76 handle. Initial validation and evidence checks precede SQL acquisition; reread the same owning handle and exact evidence around awaited boundaries. A foreign handle or historical observation must not acquire SQL.

Generate32 cryptographically random bytes internally for a canonical43-character base64url secret, hash its ASCII representation with SHA256, and generate independent family/generation UUIDs internally. No caller entropy, family ID, generation ID or credential is accepted. SQL receives only the digest and internally generated IDs. The canonical request digest binds the complete derived evidence/selector/family/generation/credential-digest tuple. Admission uses one fixed27-TEXT SQL function contract agreed by the SQL/application engineers before either implementation; the shared exported SQL string and exact parameter order are the executable contract. The reply has exactly six TEXT fields: `outcome,family_id,generation_id,provider_binding_id,expires_at_ms,audit_id`. Validate one closed row, exact IDs/digests/expiry and outcome before COMMIT.

Only `newly_admitted` with observed COMMIT, completed disposable-client release and a final fresh owning-evidence check may return the new private credential once. All replay/reconciliation/denial/conflict/uncertainty returns carry no secret. A lost COMMIT/release does not permit a retry, credential reconstruction or a replacement family. Read-only reconciliation reports terminal attribution only. Bound attempt/acquisition/statements by the strict own evidence deadline and a five-second attempt cap; discard late connections, cancel work, await cleanup and keep provider text/raw errors/secrets out of public diagnostics. This private local interface does not return an ActorRef, HostContext, cookie or grant.

## Durable model and atomic behavior

Provider binding uniqueness is `(provider, environment, client, providerSessionId)`, tied immutably to one stable mapping and exact verification profile. Active association does not guarantee provider liveness. Family and generation are independent durable concepts with digest-only secret storage. Initial local family/generation lifetime is15 minutes from database time, with no sliding extension or refresh transport; the five-second evidence lease is only the admission fence. Fresh owning evidence can create another family while the provider binding is unrevoked, without extending an existing family or reviving a revoked binding. Do not infer provider token expiry from evidence expiry.

Use a safe separate NOLOGIN `morrow_identity_sessions` executor with no table/owner/service memberships. It can invoke only fixed admission/read-only reconciliation functions. The transaction takes consistent locks on current profile/mapping/explicit profile binding/principal/selected organization/workspace/memberships/policy and the applicable provider/family/generation rows. Re-resolve, compare expected IDs/revisions and recheck active state/database expiry after waits and immediately before persistence. Command, request digest, exact tuple, provider binding, one family/generation and immutable audit are atomic; altered bindings conflict and identical concurrent requests persist one result. Dedicated owner-only fixed revocation functions may audit and permanently invalidate provider bindings/families/generations for this local qualification; they have no public/API/session-role execution privilege and do not implement an end-user authorization flow.

Authority consumption always receives explicit per-request workspace selection and rechecks current provider/profile/mapping/explicit binding/family/current generation/lifetime/revocation/principal/organization/workspace memberships/policy. It must deny if the credential digest exists in both old and new representations. In migration8 replace the read boundary and migration4/5 writer definitions together through one shared eligibility/lock helper. Preserve existing receipt/grant/proof/command/nonce/audit behavior. Session/identity invalidation while a mutation waits must deny after the lock; workspace revocation cannot silently retarget another tab or revoke independently eligible access to another workspace. Do not write synthetic composite IDs into legacy sessions.
