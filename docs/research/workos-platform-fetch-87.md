# Fixed WorkOS requests in the pinned Workers runtime

Canonical sequence 87 qualifies a private captured Workers Fetch constructor before controlled Neon role clients. Canonical sequence 86 qualified injected synthetic Fetch; it did not establish that every request option worked in native Workers. Node and the synthetic constructor retain their existing `redirect:error` policy. The new private Workers constructor uses `manual` and rejects every non-200 response without following it.

The installed versions are Miniflare 4.20260730.0 and workerd 1.20260730.1, with compatibility date 2026-07-30 and nodejs_compat. The exact tagged [Request parser](https://github.com/cloudflare/workerd/blob/v1.20260730.1/src/workerd/api/http.c%2B%2B#L536) accepts follow/manual and rejects error. This is a fact about the pinned implementation, rather than a claim about every current Fetch implementation. The [general Workers Fetch documentation](https://developers.cloudflare.com/workers/runtime-apis/fetch/) is supporting API context; actual pinned execution remains necessary.

Workerd builds the caller response URL list from its request and follows only the follow policy. Its [response attributes](https://github.com/cloudflare/workerd/blob/v1.20260730.1/src/workerd/api/http.c%2B%2B#L1385) and [response construction](https://github.com/cloudflare/workerd/blob/v1.20260730.1/src/workerd/api/http.c%2B%2B#L1953) support measuring URL/redirected inside the Worker. Preserve a held result if the actual platform exposes an empty or unexpected URL; never stamp a trusted URL onto a response.

Miniflare's installed outboundService callback uses an internal HTTP bridge. It reconstructs the Node-side Request and writes status/headers/body back; callback Request.redirect/signal and a constructed Response.url do not preserve the caller's original Fetch options or response provenance. The installed Miniflare index.js SHA256 is 25f0935c66e24b503a64561e77625b1dd163995ce2177485e3be48d05bde7d45. Its response writer can encode a decoded body according to Content-Encoding and remove Content-Length. Supply one encoding pass and inspect the actual Worker-visible headers and bytes. Workerd's no-store handling can add cache-control/pragma; distinguish these measured platform additions from the adapter's fixed headers.

The independent local oracle registers the actual authorization challenge/client/callback before receiving the code POST, then checks S256 from the submitted verifier against that independently captured challenge. Native RSA tokens and public keys pass through actual captured Fetch and the unchanged owning verification/admission chain. The oracle never delegates to Internet Fetch. Successful chains have positive intercepted platform calls and zero actual Internet/WorkOS calls; those are separate counters.

Real HTTP can represent redirects, status/media errors, malformed bytes, oversized bodies, controlled delayed replies and streams. Arbitrary Response attribute replacement, non-Response values, nonbyte reader chunks and rejected custom reader.cancel promises remain covered by the existing sequence 86 injected transport tests where this bridge cannot represent them. Local cancellation acknowledgement is separate from whether attributable Node fixture work stopped. These tests do not qualify WorkOS DNS/TLS/account access, hosted secret custody, a browser engine, Workers→Neon transport or merchant activation.
