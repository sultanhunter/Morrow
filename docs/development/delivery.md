# Delivery baseline and remaining qualification
Canonical sequence26. `npm run ci` runs formatting of new application/P03 sources, strict typing, source/schema/import/known-secret/migration checks, all tests, framework builds and the no-dispatch lab. `smoke:scaffold` starts loopback-only processes, verifies denied real entries and development fixture behavior, then terminates them. Existing P01 documentary scripts are preserved; generated contracts are checked against their generator rather than independently reformatted. Node24.13.0/framework versions and npm lock are pinned. Dependency audit identifies advisories, not complete supply-chain assurance; compatible Vite/esbuild security patches are applied before baseline acceptance.

GitHub workflow uses read-only repository permissions, immutable official action commits, no persisted Git credential, pull_request (not pull_request_target), no provider secrets and no deployment step. It is prepared locally; a repository/host run is required before claiming CI or protected-review enforcement. Configure default-main protection: required foundation status and pull request review, dismiss stale approvals, require conversation resolution, no force pushes/deletions, no administrator bypass for release. Name actual owners/reviewers before CODEOWNERS, never invent a team handle. Keep deployment credentials/environments separate from untrusted pull requests. No remote or GitHub plan upgrade is implied by the file. Pin provenance checked 6October2026: https://github.com/actions/checkout and https://github.com/actions/setup-node.

Migrations: immutable NNNN.slug.sql, sequence, SHA-256 and reviewed evidence reference in migrations/manifest.json. Every file must be listed; changes/reordering/checksum drift reject. The initial manifest has zero migrations because no database exists. This gate checks metadata, checksum and transaction envelope, not SQL grammar or PostgreSQL behavior. P04 must apply against the selected real PostgreSQL engine, inspect roles/RLS, prove rollback/recovery and reject semantic failures before any database deployment. Exceptional nontransactional migrations need a reviewed separate operational procedure; don't disable the envelope gate casually. Contract schema changes also require compatibility/evaluation/consumer and migration receipts before deliberately updating the documentary freeze.

Secret scan covers recognizable keys/private-key headers and credential literals, reports path/category only, never secret values. It is bounded assurance, not proof of no secrets or replacement for provider revocation. Suspected leaks block and require rotation/review via actual owner; fixture keys used for negative tests are constructed in memory. No credential is ever needed in CI. The production security/isolated-runtime gates remain P12/P18.

Evidence index records packet status, source hashes, cases, scope and remaining gates. Reviews explicitly distinguish Codex self-review from independent review, real merchant usability and provider permissions. Qualification is not obtained by ignoring a check or relabelling test fixtures.

Initial private repository has only a README on main. The foundation branch also triggers push CI so its workflow can be qualified before merging any application code. PR/main checks remain; this bootstrap trigger does not confer release approval or bypass review.
