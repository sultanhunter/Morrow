# Permission kernel candidate
Canonical37. P05.T02a is a server-only human permission evaluator and fresh-authority reader interface; it supplies no database reader, HTTP authorizer, authenticated route or provider dispatcher. It consumes closed version-one contracts without changing the freeze. Local fixtures are not trusted production identity.

Requests identify one capability, verb, exact resource, separate actual provider account and nonempty unique field paths. Client identity/grants/role fields are rejected. Connection IDs and provider account IDs are distinct; the latter must match server-resolved ownership, not be inferred from a connection ID. Request values are bounded plain JSON, copied and frozen before an asynchronous reader can observe them. Accessors, symbols, sparse/custom arrays, unknown fields, invalid paths, prototypes and arbitrary upstream errors fail with fixed safe codes.

Each call obtains current identity/membership/session/workspace/organization facts, current owned resource/account and a grant snapshot whose revision equals the current policy revision. No allow is cached. Individual grants may have older issuance revisions but not future ones; revoked, expired, future-valid, mismatched-principal and wrong-issuer grants are ineligible. Duplicate grant IDs are ambiguous and reject. One explicit grant must cover the complete capability/verb/resource/store/account/field request; unrelated partial grants cannot widen it through composition. Empty scope lists confer no all-store/all-account/all-field authority. A store/account-specific grant cannot become an accountless workspace grant. The live reader/transaction boundary and grant lifecycle still require SQL integration, serialization and revocation-sensitive cache qualification.

Merchant human authority requires real active membership, a current human session and no installation/mandate actor fields. Agents, service principals, installed-agent identities and automation deny until P05.T04 adds its explicit intersection. Platform author/evaluator/publisher/revoker capabilities deny through this merchant kernel, even with an invented matching grant; platform publishing needs a separately qualified first-party namespace. Role titles do not add grants.

View/propose/approve/execute/delegate/administer are distinct canonical verbs. Connection setup requires the exact governance.connection.connect capability/administer pair; no seventh Grant-schema verb is invented. An allowed decision declares permission eligibility and returns execution obligations. Exact approval, budget reservation, current-policy dispatch recheck and provider-effect verification remain independent controls; a permission decision cannot be used as an approval token or provider dispatch receipt. Domain handlers must derive the correct resource/account/field list from their actual payload and qualify these controls before exposing reads, export, retrieval or commands. This kernel does not authorize arbitrary fields merely by trusting an agent's field list.

Canonical PolicyDecision values and fixed safe messages never echo denied identifiers or provider payloads. Fresh facts are read again after membership removal; grant expiry is evaluated after the reader returns. Equivalent sessions can have different decision IDs/times while producing the same allowed/reason/policy result. A past decision must never be persisted as reusable execution authority.
