# Identity persistence candidate
Canonical sequence35. P05.T01a supplies the first application SQL migration and server-only read interface; no real route is authenticated, no session issuer or production pool is configured. Follow the canonical packet, not this explanatory document as a second plan.

The maintenance role morrow_identity_owner is NOLOGIN/NOBYPASSRLS and owns only the new schema objects. Its explicit owner policy allows controlled identity lifecycle maintenance; FORCE RLS is not a claim that privileged maintenance cannot read data. The runtime morrow_api role cannot inherit that role, create schema objects, write identity tables or read sessions/principals/memberships. Regional IAM/TLS/login, role graph and actual environment isolation still require P04 qualification. The prerequisites file is documentary; nothing is applied to a hosted database; canonical45 selects Neon.

Organization and workspace activation defaults false. Composite foreign keys bind workspace assignments to the same organization as membership. Session records contain only a digest of a future opaque Morrow session and an internal WorkOS session reference; no email matching, unverified JWT claim or client tenant ID can create a membership. The digest is bearer-equivalent sensitive material. Only a qualified future issuer may write it after provider verification; local fixture inserts never establish real authentication. No proof values appear in evidence, command arguments, environment variables or repository fixtures.

A fixed-search-path security-definer function resolves the transaction's server session digest and requested workspace against current active organization/principal/membership/assignment and current session expiry/revocation. Client workspace selection is merely a filter. The two runtime-readable projections are column restricted and RLS protected. Other merchant tables have no runtime read privilege. Temporary/public objects cannot substitute function dependencies. Domain capability/store/resource/field grants are a separate P05.T02 boundary; even valid identity metadata confers no execution grant. Do not expose this read interface as a merchant API before shared authorization is implemented.

The typed persistence port always uses one acquired connection, a READ COMMITTED read-only transaction, bounded SQL/idle timeouts and parameterized values. It verifies both login and current role are the unprivileged service role; a superuser connection using SET ROLE is rejected. Context is SET LOCAL and rollback/commit clears it. Closed result validation accepts only canonical ActorRef/positive safe revisions. Arbitrary database/callback errors are reduced to fixed codes, and failed rollback discards the connection. A retained read scope cannot use a released connection. This is an injected port; the production PostgreSQL driver and qualified WorkOS session boundary remain follow-on work.

Local evidence applies the exact migration on the pinned official PostgreSQL17.11 image. A different unprivileged SQL login exercises RLS and privilege denials. The attack cases deliberately use a normal read/write transaction so denied writes do not pass merely due to the application wrapper's read-only setting. A second connection revokes membership between two statements of an existing READ COMMITTED transaction; the later protected read observes zero rows. This does not cancel a read already in progress. Future commands/dispatch must serialize against current authority and obey live grant revisions; transaction-wide historical snapshots cannot qualify current authority. The local Unix socket trust configuration exists only within a newly owned network-disabled ephemeral container and is not production login assurance.

Provider-backed session mint/refresh/logout/revocation, audited organization/membership/team/service commands, verified provisioning replay, SSO/SCIM, permission-sensitive caches, linking and delegated automation are still pending. No P05 end-to-end acceptance or live activation is claimed. Sources: [PostgreSQL row security](https://www.postgresql.org/docs/17/ddl-rowsecurity.html), [security-definer precautions](https://www.postgresql.org/docs/17/sql-createfunction.html), [node-postgres transactions](https://node-postgres.com/features/transactions), [parameterized queries](https://node-postgres.com/features/queries).
