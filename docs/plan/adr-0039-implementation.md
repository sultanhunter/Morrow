## The note for ADR-0037 (pull request 72)

To append under ADR-0037's Amendments when it reaches `main`, unless it already says the same:

> ### 2026-10-25: item 6 and the money lines, credits are the only spend limit (ADR-0039)
>
> The owner's decision of 2026-10-25 (OD-2026-10-25-4, recorded in ADR-0039) changes these lines; the text above is kept as approved.
>
> - **Item 6 ("Money").** No created-teammate caps (5% of the monthly grant per run, 20% per workspace per day), no per-installation caps, no US$7 or US$25. A teammate's run, of either origin, called or handed off, holds and draws its own credits from the workspace's wallet like any run; Morrow's run never holds credits for its children.
> - **Item 3(a).** A call whose run the wallet cannot cover returns `insufficient_credits` to Morrow at once, in place of "does not fit the daily backstop".
> - **Item 5.** The spend class is discounts; "caps above the rate card's defaults" lapses, since the rate card has no caps.
> - **Item 10.** Raising the daily backstop for eval days lapses; eval rounds draw credits.
> - **"Does not change" and Consequences.** The US$7 and US$25 backstops and item 6's caps no longer exist.

## Not in these PRs

Each needs its own decision: an optional credit limit that the Owner sets per agent or per workspace; a count limit on proactive runs, only if staging shows bursts (ADR-0039, Consequences); rate card v1's publication with the plan price and grant (ADR-0026 items 5 and 6); raising the owner's test credits (a staging BillingTerms revision); lifting `UsageCap`'s platform ceiling (ADR-0026 owner question 3).
