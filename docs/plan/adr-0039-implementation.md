# ADR-0039 implementation: credits are the only spend limit

- Record: the code PRs of [ADR-0039](../decisions/adr/ADR-0039-credits-only-spend-limit.md) (credits are the only spend limit), accepted 2026-10-25 (OD-2026-10-25-4). The cap inventory, with file and line, is in the record's Consequences.
- Written 2026-10-25 from `main` at `ad4700a4`, after ADR-0036 merged (pull request 70, catalogue version 3, migration 0051). No code lands with the ADR.
- Rules: each PR is small, on a short-lived `claude/` branch, with its tests and one AI review (separate context, same model family) with the security lens, since every PR here touches budgets; stacks at most two deep. Sizes: S (a day or less), M (two to three days), L (a week, usually two PRs).
- Changed 2026-10-26 for [ADR-0041](../decisions/adr/ADR-0041-harness-foundations.md) (harness foundations, Accepted, OD-2026-10-26-7), which amends ADR-0039 items 2(c) to 2(g), 4, 5, 6 and 9 (the dated note in ADR-0039, 2026-10-26): when a step's hold cannot be covered the job pauses instead of taking a final turn from a reserve (owner question 6); holds follow the cache (question 8); reliability and upkeep steps are paid, and a failed ending is refunded at settlement (question 7); stop conditions become safety check-ins; catalogue version 4 is Opus 5.5 at `medium` and `high` only (question 1). Row 1 is now harness plan H3, row 3 is H8, and row 2 splits between this plan, H6 and H8, in [harness-foundations-implementation.md](harness-foundations-implementation.md); rows 5 to 8 change as noted.
- Changed again on 2026-10-26 for OD-2026-10-26-12 (credits are the only budget, pull request 89; the 2026-10-26 Amendments of ADR-0039, ADR-0040 and ADR-0041): what H8 builds in place of the third PR loses the platform breaker's pause at 80% of the owner's Anthropic monthly limit, which becomes an alert to the owner that pauses nothing, and the cost check-in; no PR here sets a cap on requests per person; beside the balance, the only budgets are the Owner's settings counted in credits, the optional per-agent credit limit (PR 7) and the member credit ceiling.
- Migration numbers below are the next free ones when each PR starts. On 2026-10-26 migrations 0001 to 0056 are applied and immutable (0056 is PR 1's, merged as pull request 83), and each PR takes the next free number when it ships. An applied migration is never edited: every SQL change here is a forward migration that replaces a helper from its pinned body (an md5 guard on `prosrc`, as 0051 did), except on pull request 64's own migration while that is still unmerged and unapplied.

## The owner's answers (OD-2026-10-26-1)

The owner answered the four readings on 2026-10-26, as recommended:

- **A loop run that fails draws nothing.** PR 3's settlement releases a failed run's holds and draws nothing, its uncertain turns included, and records the metered cost as Morrow's own. Which end reasons count as failed is ADR-0039 item 2(g)'s list, answered by the owner (OD-2026-10-26-2): an error on Morrow's side or the provider's is free; a run that gives an answer or that a person stops is charged. *2026-10-26 (ADR-0041 item 9; OD-2026-10-26-7, question 7):* every send still holds and draws whatever the end, and "free" for a failed ending is a refund recorded at settlement, never a skipped hold; the limit endings item 2(g) lists no longer exist.
- **A breaker for runs that keep failing** (OD-2026-10-26-2): PR 8, before the first outside merchant.
- **The final-turn reserve stood, then was replaced the same day.** The owner confirmed it on 2026-10-26 (OD-2026-10-26-1), then replaced it with pausing the job when credits run out (OD-2026-10-26-7, question 6; ADR-0041 item 9), under the owner's rule of no finishing a job near a limit with an answer (OD-2026-10-26-6). No PR builds the reserve.
- **`UsageCap`'s platform ceiling stays** (ADR-0026 owner question 3). It is not in these PRs; it lands with the Shopify billing code.
- **An optional per-agent credit limit** that the Owner sets, none by default, is PR 7, whose design below is the lead's proposal.

The runtime budget's removal (PR 4) was never among the readings: it falls under the lead's "any other hardcoded money ceiling".
